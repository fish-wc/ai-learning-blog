# 学习路线

这条路线服务于一个明确目标：能够独立完成 AI 应用或大模型相关项目，并能从原理、代码、指标和工程取舍四个层面把项目讲清楚。路线不是一次性完成的课程表，而是随着实践不断修订的检查清单。

## 学习闭环

```text
提出问题 → 阅读资料 → 动手实现 → 设计实验 → 记录指标 → 复盘表达 → 沉淀项目
```

每个主题至少留下三类内容：

- **概念**：用自己的话解释它解决什么问题，以及关键假设是什么。
- **实践**：最小可运行代码、环境版本、输入输出和复现实验。
- **判断**：与其他方案的对比、失败原因、适用边界和下一步计划。

## 推荐主线

### 1. 基础能力

先补齐 Python 工程、Linux、Git、数据结构、概率统计、机器学习和深度学习基础。目标是能够读懂实现、定位问题，并写出质量稳定的实验代码。

### 2. 大模型基础

理解 Tokenization、Transformer、Attention、预训练目标、微调方法、推理流程和评测方式。目标是能从输入到输出解释模型的主要计算过程。

### 3. RAG 与数据

从文档清洗开始，掌握切分、Embedding、向量检索、混合检索、重排、上下文构造和端到端评测。目标是能定位 RAG 系统的瓶颈，而不是只会调用框架。

### 4. Agent 与工作流

学习工具调用、结构化输出、状态管理、记忆、规划、反思和多 Agent 协作，并重点关注可靠性、成本、延迟和安全边界。目标是能把开放式任务拆成可观察的工作流。

### 5. AI Infra

补充 GPU 与并行计算基础，实践模型服务、批处理、缓存、量化、推理优化、分布式训练和监控。目标是理解一个模型系统如何稳定、低成本地服务用户。

### 6. 项目与面试

用端到端项目串联知识：明确需求，做出基线，建立评测集，迭代方案，记录指标，并整理成 README、技术文章和面试讲稿。

## 阶段检查点

| 阶段 | 能力检查 | 输出物 |
| --- | --- | --- |
| 基础 | 能独立读写、调试和测试 Python 项目 | 基础实验笔记 |
| LLM | 能解释 Transformer，并完成一次微调或推理实验 | 原理笔记 + 实验报告 |
| RAG | 能建立离线评测并定位检索/生成问题 | RAG Demo + 指标 |
| Agent | 能设计可观测、可恢复的工具工作流 | Agent 项目 + 失败案例 |
| Infra | 能描述吞吐、延迟、显存和成本之间的取舍 | 服务化/优化实验 |
| 求职 | 能用 STAR 结构讲清项目取舍和结果 | 项目 README + 面试题 |

## 每周节奏

1. 选择一个足够小、能够在一周内验证的问题。
2. 先做基线，再只改变一个变量进行对比。
3. 把结果写成一篇短笔记，不追求一次成稿。
4. 周末复盘：哪些结论被证实，哪些假设被推翻，下一周要补什么。

> 学习路线的完成标准不是勾满所有项目，而是形成持续输出、可复现和能解释的工程能力。
