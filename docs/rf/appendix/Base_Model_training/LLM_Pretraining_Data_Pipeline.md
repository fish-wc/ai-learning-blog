# Day 18｜LLM 预训练数据：为什么 Raw Web Data 不能直接拿来训练？

> **LLM Pretraining Data Pipeline：从互联网原始数据到高质量训练语料**
>
> 📖 核心论文：[Deduplicating Training Data Makes Language Models Better](https://aclanthology.org/2022.acl-long.577/) — Lee et al., ACL 2022
>
> **关键词：** Pretraining、Common Crawl、Data Quality、Deduplication、Decontamination、Tokenization、Data Mixture
>
> **本文目标：** 理解为什么不能简单地把互联网数据直接用于大语言模型训练，以及如何通过一套数据处理流水线，将原始网页转化成适合预训练的语料。

---

## 一、引言：为什么有了互联网，还需要构建训练数据集？

在学习大语言模型（Large Language Model，LLM）的过程中，我们经常会听到这样的说法：

“大模型是在海量互联网文本上预训练出来的。”

这句话本身没有错，但很容易让人产生一种误解：

**是不是只要把互联网上的网页全部爬下来，转换成 Token，然后交给 Transformer 训练，就能得到一个优秀的大语言模型？**

从技术上说，只要完成必要的文本解析和 Tokenization，确实可以使用未经充分清洗的互联网文本训练模型。

但这样做通常不是一个好的选择。

原因在于：

**互联网数据的分布，并不等于我们希望模型学习的数据分布。**

互联网包含大量有价值的信息，例如：

* 教材、论文和技术文档；
* 新闻报道和百科知识；
* GitHub 开源项目及其文档；
* 论坛中的真实问题与讨论；
* 文学作品、博客以及各种专业文章。

但同时也充斥着：

* SEO 垃圾网页和广告；
* 大量转载、镜像和重复内容；
* 网页导航栏、页脚以及 HTML 模板；
* 乱码、不完整句子和机器生成的低质量文本；
* 可能泄露个人隐私的信息；
* 不适合直接纳入训练的有害内容；
* 已公开的模型评测题目及答案。

如果把这些数据不加区分地用于训练，就会产生一个问题：

**模型并不知道哪些内容值得学习，它只会根据训练目标和训练过程中看到的数据调整参数。**

因此，在真正开始训练之前，我们需要先解决一个更基础的问题：

> 如何从庞杂的原始互联网数据中，构建一个质量更高、分布更合理、风险更可控的训练语料库？

这就是 **Pretraining Data Pipeline（预训练数据处理流水线）** 要解决的问题。

## 二、从模型训练原理出发：为什么数据分布如此重要？

要理解为什么必须清洗数据，我们需要先回到大语言模型最基本的训练目标。

### 2.1 模型究竟在学习什么？

对于典型的自回归语言模型（Autoregressive Language Model），预训练的核心任务是：

**根据前面已经出现的 Token，预测下一个 Token。**

给定一个 Token 序列：

$$
x_1,x_2,\ldots,x_T
$$

其中：

* \(x_t\)：序列中第 \(t\) 个 Token；
* \(T\)：Token 序列长度；
* \(\theta\)：语言模型的可学习参数；
* \(P_\theta(x_t\mid x_{<t})\)：模型根据之前的 Token，预测当前 Token 的概率。

模型通常通过最小化负对数似然损失进行训练：

$$
\mathcal{L}(\theta)
=
-\frac{1}{T}
\sum_{t=1}^{T}
\log P_\theta(x_t\mid x_{<t})
$$

这个公式看起来有些抽象，但含义很直观。

假设训练文本是：

> The capital of France is Paris.

模型读到：

> The capital of France is ...

它需要预测下一个 Token。

如果模型给正确 Token 分配的概率越高，那么对应的损失就越小。

通过不断训练，模型逐渐学习语言结构、事实关联、常见表达方式，以及训练数据中隐含的各种统计规律。

### 2.2 这个训练目标存在什么问题？

关键在于：

**Next Token Prediction 本身并不会判断训练文本是否真实、可靠或者有价值。**

对于训练算法来说：

一篇科学教材中的句子，会参与损失计算。

一个垃圾网站中的广告，也会参与损失计算。

如果同一段广告因为网站转载而被复制很多次，它同样会反复参与训练。

模型不会天然知道：

“这段内容在互联网上出现很多次，只是因为垃圾网站互相复制，并不代表它重要。”

于是，我们就需要思考重复数据对训练目标的影响。

### 2.3 为什么重复数据会改变模型学习的重点？

假设我们有两篇不同的文档：

* 文档 A：一篇优秀的机器学习教程。
* 文档 B：一篇充满广告的网页。

文档 A 只出现一次。

文档 B 因为被许多网站复制，出现了 \(k\) 次。

为了便于理解，假设两篇文档长度相同，训练时也按相同方式采样。

那么训练损失可以简化为：

$$
\mathcal{L}(\theta)
=
\frac{
\ell_A(\theta)+k\ell_B(\theta)
}{
1+k
}
$$

其中：

* \(\ell_A(\theta)\)：文档 A 对模型产生的损失；
* \(\ell_B(\theta)\)：文档 B 对模型产生的损失；
* \(k\)：文档 B 的重复次数。

进一步对模型参数求梯度：

$$
\nabla_\theta\mathcal{L}
=
\frac{
\nabla_\theta\ell_A+
k\nabla_\theta\ell_B
}{
1+k
}
$$

这里出现了非常重要的现象：

**重复次数越多，重复文档在整体训练目标中的相对权重就越高。**

需要注意，这并不是说模型一定会逐字背下所有重复内容，也不意味着某个参数更新会简单地放大 \(k\) 倍。真实训练还受到文档长度、采样策略、Batch 构成、优化器等因素影响。

但是，在其他条件相同时，重复数据确实会提高相关内容在训练中的曝光频率和相对权重。

这样一来，互联网中的重复频率，就可能被模型错误地当成某种需要重点学习的统计信号。

这正是数据去重（Deduplication）具有重要意义的原因。

### 2.4 数据清洗的本质是什么？

经过前面的分析，我们可以建立一个更准确的理解：

**数据清洗并不只是删除垃圾内容，更是在重新设计模型所面对的训练数据分布。**

从数据科学角度看：

原始互联网数据对应一个分布：

$$
P_{\text{raw}}(x)
$$

经过过滤、去重、采样和混合后，实际用于训练的数据对应：

$$
P_{\text{train}}(x)
$$

我们希望通过数据处理，使训练分布更加符合模型的目标能力和使用需求：

$$
P_{\text{raw}}(x)
\longrightarrow
P_{\text{train}}(x)
$$

这里必须强调：

我们通常并不知道所谓“最优训练分布”究竟是什么。

实际工程中，需要根据下游任务表现、数据多样性、训练效率和风险评估等指标，不断调整数据处理策略。

这也是为什么构建高质量预训练语料本身就是一个重要的研究方向。

## 三、预训练数据流水线：从 Raw Web 到 Training Corpus

现在我们可以尝试设计一条完整的数据处理流水线：

```text
                 Raw Web Data
                       |
                       v
                    Crawl
                       |
                       v
                Language Filter
                       |
                       v
                 Quality Filter
                       |
                       v
               Safety / Filtering
                       |
                       v
                     Dedup
                       |
                       v
                Decontamination
                       |
                       v
                   Tokenize
                       |
                       v
                    Mixture
                       |
                       v
              Pretraining Corpus
```

这条流水线可以归纳成八个核心问题：

| 阶段                 | 需要回答的问题           | 主要目标        |
| ------------------ | ----------------- | ----------- |
| Crawl              | 数据从哪里来？           | 收集原始语料      |
| Language Filter    | 需要保留哪些语言？         | 控制语言分布      |
| Quality Filter     | 哪些文本具有训练价值？       | 提高文本质量      |
| Safety / Filtering | 哪些内容需要删除、脱敏或特殊处理？ | 降低数据风险      |
| Dedup              | 哪些内容被重复收集？        | 减少重复带来的分布偏差 |
| Decontamination    | 训练数据是否泄露评测集？      | 提升评估可信度     |
| Tokenize           | 如何把文本转换成模型输入？     | 构建 Token 序列 |
| Mixture            | 不同数据源应该如何组合？      | 设计最终训练分布    |

**说明：这是一条便于学习的概念流水线，并不是所有工业系统都遵循的固定执行顺序。**

例如，实际系统通常在 Crawl 之后先进行 HTML 解析和正文提取；安全过滤可能发生在多个阶段；Mixture 可以在最终 Tokenization 之前制定，也可以在训练数据加载时动态实现。

Hugging Face 的 FineWeb 就提供了一套公开的数据处理实现，可以作为工程参考。[5]

接下来，我们逐步理解每一个阶段。

---

## 四、Crawl：从哪里获得预训练数据？

### 4.1 Crawl 是什么？

Crawl 即网络爬取。

它的目标是从互联网中收集网页内容，作为后续数据处理的原始材料。

在大模型预训练领域，一个非常重要的公开数据来源是：

**Common Crawl。**

官方网站：

https://commoncrawl.org/

Common Crawl 是一个提供开放网络抓取数据的项目。

它周期性地抓取互联网网页，并提供数据供研究人员和开发者使用。[2]

不过，Common Crawl 并不是专门为大语言模型训练而设计的。

它的主要任务是收集网页，而不是判断网页是否适合训练模型。

因此：

**Common Crawl ≠ 可以直接使用的高质量预训练语料。**

### 4.2 抓下来的网页是什么样的？

我们平时看到的网页往往经过浏览器渲染。

但爬虫获得的数据可能包含：

```html
<html>
  <head>
    <title>Machine Learning Tutorial</title>
  </head>
  <body>
    <nav>Home | About | Contact</nav>
    <h1>Introduction to Machine Learning</h1>
    <p>Machine learning is a field of AI...</p>
    <footer>Copyright | Privacy Policy</footer>
  </body>
</html>
```

这里真正值得模型学习的内容可能只是：

> Introduction to Machine Learning
> Machine learning is a field of AI...

而导航栏、页脚和其他模板信息未必具有同样的训练价值。

因此，在真正过滤数据之前，一般还需要完成：

* HTML Parsing：解析网页结构；
* Text Extraction：提取正文；
* Boilerplate Removal：去除导航栏、广告和重复模板；
* Encoding Normalization：统一字符编码。

Common Crawl 提供不同的数据格式，包括：

* **WARC**：原始网页抓取数据；
* **WAT**：从抓取数据中提取的元信息；
* **WET**：提取后的纯文本内容。

即使是 WET，也不意味着其中所有文本都是高质量正文。[2]

因此，Crawl 阶段的作用只是：

**尽可能获取候选数据，而不是直接生产最终训练数据。**

## 五、Language Filter：为什么要进行语言过滤？

假设我们准备训练一个主要面向英文任务的大语言模型。

但原始互联网中包含：

* 英文文章；
* 中文文章；
* 日文文章；
* 法文文章；
* 英中混合文本；
* 程序代码；
* 无法识别语言的乱码。

如果直接使用全部数据，训练语料中的语言比例将受到爬虫覆盖范围和网页数量的影响。

而这种比例不一定符合我们的训练目标。

### 5.1 Language Filter 做了什么？

语言过滤通常首先识别文档的语言。

例如，使用 fastText 等语言识别模型，对文档进行分类，得到类似：

$$
P(\text{English}\mid d)
$$

这里：

* \(d\)：待检测文档；
* \(P(\text{English}\mid d)\)：文档被判断为英文的置信分数或模型输出的概率估计。

然后，根据设定的阈值决定是否保留。

例如：

> 当英文识别分数达到预设要求时，将文档纳入英文语料候选集。

FineWeb 就采用了基于 fastText 的英文过滤策略。[5]

### 5.2 为什么不能直接理解为“英文好，中文不好”？

Language Filter 的目的不是评价语言本身的价值，而是**控制训练数据的语言组成**。

对于英文模型，中文内容可能被排除。

但对于多语言模型，中文、英文和其他语言都可能是非常重要的训练数据。

此时，工程师需要分别处理不同语言的数据，并在后续 Mixture 阶段控制各语言的占比。

还需要注意，语言识别器也可能误判：

* 代码和自然语言混合的文本；
* 少数语言和方言；
* 多语言技术文档；
* 短文本。

因此，语言过滤越严格，并不意味着训练数据一定越好。

这里我理解到的核心是：

> Language Filter 不只是语言识别，更是在控制模型接受哪些语言的数据，以及这些数据的后续采样机会。

## 六、Quality Filter：为什么看起来正常的网页也可能不适合训练？

Language Filter 解决了“语言是否符合要求”的问题。

但它没有解决“内容是否值得学习”的问题。

例如：

```text
BUY NOW!!!
BEST PRICE!!!
CLICK HERE!!!

Home
About
Contact
Privacy Policy

BUY NOW!!!
BEST PRICE!!!
CLICK HERE!!!
```

这些文本可能完全符合英文识别条件。

但它们存在大量重复、模板化和广告信息。

如果直接用于训练，会占用训练预算，却不一定提供足够有价值的语言学习信号。

### 6.1 Quality Filter 的目标

Quality Filter（质量过滤）的主要目标是：

**识别并减少低质量、低信息密度或明显异常的文本。**

常见的过滤信号包括：

| 信号                   | 可能发现的问题        |
| -------------------- | -------------- |
| Document Length      | 过短、缺乏正文的页面     |
| Word Length          | 异常长词、乱码        |
| Symbol Ratio         | 标点或特殊符号过多      |
| Repetition Ratio     | 大量重复句子或段落      |
| Stopword Statistics  | 不符合正常语言表达的文本   |
| Boilerplate Patterns | 导航栏、广告和网页模板    |
| Perplexity           | 与参考语言分布差异较大的文本 |
| Quality Classifier   | 与目标高质量文本特征不匹配  |

实际系统不一定使用所有信号，而是按照成本、语言特点和下游效果进行组合。

### 6.2 质量过滤不等于判断文本的真实性

这是一个很容易混淆的概念。

一篇文章可能：

* 语法非常正确；
* 结构非常清晰；
* 表达非常流畅；
* 但事实内容是错误的。

传统的启发式质量过滤可能认为这篇文章具有较高质量。

因此：

**文本质量、事实正确性和内容安全性不是同一个概念。**

Quality Filter 通常无法独立完成事实核验。

### 6.3 过滤是不是越严格越好？

不是。

假设一个过滤器把“和百科全书写作风格很相似”作为高质量标准。

那么它可能偏爱：

* 正规书面语；
* 百科式定义；
* 标准学术表达。

但同时排斥：

* 口语化表达；
* 方言；
* 论坛中的真实问题；
* 非标准但有价值的专业讨论。

Dodge 等人在 EMNLP 2021 的研究中，对 C4 数据集进行了审计，发现部分基于词表的过滤策略会不成比例地移除与少数群体有关的文本。[4]

这说明：

**过滤器不仅会删除数据，还可能改变训练语料的社会、语言和知识分布。**

因此，优秀的数据处理系统不仅需要关注保留数据的质量，还需要分析被删除的数据究竟是什么。

## 七、Safety / Filtering：为什么高质量文本也可能需要过滤？

接下来是 Safety / Filtering。

它与 Quality Filter 有交集，但关注的问题不完全一样。

Quality Filter 更关心：

> 这是不是具有训练价值的文本？

Safety / Filtering 更关心：

> 这份数据是否存在隐私、安全或其他使用风险？

例如，一篇包含真实个人联系方式的文章可能写得非常好。

从语言质量角度看，它完全符合要求。

但从隐私保护角度看，某些信息可能需要删除或脱敏。

### 7.1 主要处理哪些风险？

常见的关注点包括：

* **Personal Identifiable Information（PII）**：个人可识别信息，例如某些私人电话、邮箱、身份信息等；
* 有害内容或恶意指导性文本；
* 涉及未成年人保护的敏感内容；
* 明显的恶意网页；
* 数据来源、使用授权和版权合规风险。

不同风险需要不同的处理方法。

例如：

* 对个人信息进行 Masking（脱敏）；
* 删除特定高风险内容；
* 对敏感来源设置访问限制；
* 根据合法性与数据使用条件决定是否纳入。

### 7.2 为什么不能把所有敏感内容都删除？

例如，一篇研究仇恨言论的社会学论文，可能会引用具有攻击性的句子。

但这些引用是为了分析有害语言，而不是鼓励使用有害语言。

如果过滤器只根据某些敏感词进行判断，就可能误删这类有价值的文本。

所以：

**内容涉及敏感话题，不等于内容本身有害。**

此外，预训练数据安全过滤并不能直接保证模型最终的行为安全。

模型行为还受到模型架构、训练策略、后训练、安全对齐等因素影响。

Allen Institute for AI 在 Dolma 数据集的工作中，也明确讨论了个人信息处理、内容过滤及其中存在的权衡。[6]

这一阶段最重要的理解是：

> Safety Filtering 的目的不是机械地删除所有敏感信息，而是在数据价值、风险、代表性和合法性之间做出有依据的选择。

## 八、Dedup：为什么数据去重是预训练中的重要环节？

现在来到本文最核心的部分：

**Deduplication（数据去重）。**

这一部分主要基于 Lee 等人发表于 ACL 2022 的论文：

[Deduplicating Training Data Makes Language Models Better](https://aclanthology.org/2022.acl-long.577/)。[1]

### 8.1 为什么互联网会存在大量重复数据？

因为互联网内容经常被：

* 转载；
* 镜像；
* 自动采集；
* 重新发布；
* 复制到不同网站；
* 在不同时间被重复抓取。

假设一篇优秀的技术文章出现在多个网站。

这些网站可能提供完全相同的正文，只是导航栏、页脚和发布日期不同。

如果将它们全部保留，模型就会反复看到相同或者高度相似的内容。

这会改变相关文本在训练语料中的出现频率。

### 8.2 Exact Deduplication：精确去重

首先考虑最简单的情况。

文档 A：

> Transformers use attention mechanisms to process information.

文档 B：

> Transformers use attention mechanisms to process information.

两份文档完全相同。

可以对规范化后的文本计算 Hash。

如果两个文档的 Hash 相同，就把它们视为潜在的重复文档，并依据实现方式保留其中一份。

常见的 Hash 算法包括 SHA-256 等。

需要注意，Hash 只是识别相同内容的工具，本身不理解文档语义；工程上还应考虑规范化规则和潜在 Hash 碰撞。

此外，除了整篇文档完全一致，还可能存在大量重复的段落或长文本片段。

Lee 等人的论文就研究了利用 Suffix Array（后缀数组）识别长重复子串的方法。[1]

### 8.3 Near Deduplication：近似去重

真实网页中的重复往往更复杂。

例如：

文档 A：

> Large language models learn statistical patterns from training data.

文档 B：

> Home / AI / Blog
> Large language models learn statistical patterns from training data.
> Copyright Example Website.

这两个文档不是完全一样的字符串。

但它们的主要内容高度重叠。

如果仅使用整篇文档的 Hash 判断是否相同，就可能无法发现它们之间的关系。

此时需要 Near Deduplication（近似去重）。

常见的方法包括：

* N-gram：把文本切分成连续词组；
* Jaccard Similarity：衡量两个集合的重叠程度；
* MinHash：近似估计集合相似度；
* LSH（Locality-Sensitive Hashing）：高效寻找相似候选文档。

以 Jaccard Similarity 为例：

$$
J(A,B)
=
\frac{|A\cap B|}{|A\cup B|}
$$

其中：

* \(A\)：文档 A 的 N-gram 集合；
* \(B\)：文档 B 的 N-gram 集合；
* \(A\cap B\)：两个集合共同拥有的 N-gram；
* \(A\cup B\)：两个集合全部不同的 N-gram。

当两个文档共享大量 N-gram 时，Jaccard 相似度通常较高。

MinHash 则通过构建紧凑的签名，近似估计这种集合相似度，从而减少大规模语料直接两两比较的成本。

这类技术也被应用于 FineWeb 等公开数据处理流水线。[5]

### 8.4 为什么去重能让模型变得更好？

Lee 等人的论文报告了几个重要发现。

**发现一：语言模型训练语料中的重复现象可能非常严重。**

论文指出，C4 数据集中存在一个长度为 61 个英文单词的句子，重复出现超过 60,000 次。

这说明即使是经过初步清洗的数据集，也可能包含严重的重复问题。

**发现二：去重能够明显降低模型复现训练文本的频率。**

论文在其研究设置下观察到，经过数据去重后，模型输出记忆化训练内容的频率可以降低约一个数量级。

这里的 Memorization（记忆化）可以理解为：模型在生成时逐字复现训练期间看到的文本。

这与模型真正理解知识、能够灵活迁移使用知识，并不是同一个概念。

**发现三：去重能够改善训练效率。**

论文报告，使用去重后的数据，模型可以通过更少的训练步数达到相同或更好的实验表现。

其背后的直观原因是：

模型不必在大量无意重复的内容上消耗相同的训练预算，可以获得更加多样化的训练信号。

不过，这并不意味着去重一定能降低所有模型的训练总成本。

实际效果取决于数据组成、去重方法、Token 预算和训练配置。

### 8.5 为什么不是去重越多越好？

这是理解 Dedup 的关键进阶问题。

如果两篇文章都在解释 Transformer，但使用不同的语言组织、示例和推导方式：

它们可能讨论相同的知识，但并不是没有价值的重复。

从学习的角度看，不同表达方式可能帮助模型学习更丰富的语言模式。

如果去重算法过于激进，就可能把这些有价值的差异也一起删除。

FineWeb 研究中的一个有趣发现是：

**对所有 Common Crawl 快照统一进行全局去重，并不一定比在各个抓取快照内部独立去重效果更好。**

研究团队通过实际训练对比发现，不同的去重范围会影响模型效果。[5][8]

因此，更准确的理解应该是：

> Dedup 的目标不是最大化删除的数据量，而是减少无意重复带来的不合理训练权重，同时尽可能保留有效的数据多样性。

### 8.6 我对 Dedup 的最终理解

在阅读这篇论文之前，我可能会认为：

“Dedup 就是为了减少数据集大小，节省存储空间。”

但从训练目标出发重新思考后，我发现它的意义远不止于此。

**Dedup 本质上是在修正重复内容对训练分布造成的偏置。**

一段内容在互联网上重复出现很多次，并不意味着它就具有更高的学习价值。

而去重，就是要尽量避免这种偶然的互联网重复频率直接决定模型的学习重点。

这也是我认为该论文最有启发性的一点：

**训练数据不是越多越好，重要的是数据是否提供了有效而多样的学习信号。**

## 九、Decontamination：模型是不是提前看过考试答案？

Dedup 解决的是训练语料内部的重复问题。

但还有一个非常重要的问题：

**模型评估所使用的数据，是否已经出现在模型的训练语料中？**

这就是 Data Contamination（数据污染）问题。

而 Decontamination 则是识别并尽量移除这种泄露的过程。

### 9.1 一个直观例子

假设我们用 GSM8K 测试模型的数学推理能力。

理想情况下：

模型应该根据训练期间获得的知识和能力，解决测试集中未见过的问题。

但如果 GSM8K 的某些题目和答案早已被别人发布到互联网上，并且进入了模型训练数据，会发生什么？

模型可能在训练期间已经见过相关题目。

此时它在评测中给出正确答案，可能既包含真实的数学推理能力，也受到记忆训练数据的影响。

因此：

**评测分数高，不一定完全等于模型具有对应水平的泛化能力。**

当然，训练集与测试集存在文本重叠，也不意味着模型一定是通过死记硬背作答；它只是削弱了评测结论的可信度。

### 9.2 Decontamination 如何实现？

通常会将候选训练语料与评测数据进行比对。

常见方式包括：

* Exact Match：完全相同的文本匹配；
* N-gram Overlap：连续词组重叠；
* Near-Duplicate Detection：近似重复检测；
* 对已知评测题目、答案及其变体进行专项排查。

根据具体任务，可以移除命中的训练文档，或者对数据集进行隔离和标记。

但 Decontamination 很难保证完全彻底。

例如：

题目可能被翻译、改写、重述，或者只泄露了部分解题过程。

因此，仅依赖字符串匹配无法发现所有污染情况。

### 9.3 Dedup 和 Decontamination 的根本区别

| 对比维度   | Dedup        | Decontamination |
| ------ | ------------ | --------------- |
| 主要目标   | 减少重复训练内容     | 降低评测泄露          |
| 主要比较对象 | 训练集内部文档      | 训练集与评测集         |
| 核心问题   | 相同内容是否被重复学习？ | 模型是否提前见过测试材料？   |
| 主要影响   | 训练分布、效率、记忆化  | 评估可信度和泛化判断      |

需要补充的是：Dedup 也可以用于减少训练集与验证集之间的重叠，因此二者在算法和具体操作上可能存在交集。

Lee 等人的论文也指出，部分标准数据集的验证集存在明显的训练—验证重叠问题。[1]

所以，Dedup 和 Decontamination 不是完全独立的技术体系，而是具有不同目的、但可能共用技术手段的数据治理过程。

## 十、Tokenize：文本如何真正进入 Transformer？

经过前面的清洗，我们拥有了相对高质量的文本。

但是 Transformer 不能直接处理原始字符串。

因此，还需要 Tokenization。

### 10.1 什么是 Tokenization？

Tokenization 是把文本映射为 Token 序列的过程。

例如：

> I enjoy learning machine learning.

经过某种 Tokenizer 后，可能被切分成若干 Token。

随后，每个 Token 会通过词表映射为整数 ID。

整体过程可以理解为：

```text
Raw Text
   |
   v
Tokenizer
   |
   v
Token Sequence
   |
   v
Token IDs
   |
   v
Embedding
   |
   v
Transformer
```

需要注意：

**Token 不一定等于一个完整单词。**

一个单词可能对应一个 Token，也可能被拆分为多个子词 Token。

标点、空格模式以及中文字符，也会根据 Tokenizer 的具体设计被不同方式处理。

### 10.2 为什么 Tokenizer 很重要？

因为它决定了文本如何被表示为离散的模型输入单位。

不同 Tokenizer 可能导致：

* 相同文本对应不同数量的 Token；
* 不同语言的 Tokenization 效率不同；
* 代码、数学公式和特殊符号被不同方式切分；
* 相同训练 Token 预算能够覆盖的原始文本量不同。

因此，Tokenization 不只是简单的文本转换，还会影响训练成本和模型的信息表示方式。

另外，在真实工程中，去重算法不一定必须等到最终 Tokenization 后才能执行。

部分去重方法基于字符或词级 N-gram 工作，另一些则可能使用预先 Tokenize 的序列。

也就是说：

**数据清洗与 Tokenization 的实现顺序，可以根据系统设计进行调整。**

## 十一、Mixture：为什么高质量数据也不能直接全部拼起来？

前面讨论的过滤、去重等操作，主要是在处理数据质量与重复问题。

但即使每份数据都经过清洗，仍然存在最后一个重要问题：

**不同来源的数据，应该在训练中占多大比例？**

假设我们最终收集了：

* Web：普通互联网文本；
* Code：程序代码与技术文档；
* Books：图书；
* Academic Papers：学术论文；
* Wikipedia：百科内容。

这些数据都可能具有价值。

但不同来源会提供不同类型的学习信号。

如果模型的主要目标是代码生成，我们可能希望提高代码语料的采样比例。

如果模型主要面向通用语言理解，就需要考虑更广泛的文本覆盖。

### 11.1 Mixture 的数学含义

假设语料包含 \(K\) 个数据源。

第 \(k\) 个数据源对应的数据分布为：

$$
P_k(x)
$$

我们为每个数据源设置采样权重：

$$
\alpha_k
$$

其中：

$$
\alpha_k\geq 0
$$

并且：

$$
\sum_{k=1}^{K}\alpha_k=1
$$

那么最终训练采样分布可以表示为：

$$
P_{\text{train}}(x)
=
\sum_{k=1}^{K}
\alpha_k P_k(x)
$$

这个公式意味着：

最终模型接触到什么样的数据，不仅取决于每个数据源自身有什么，还取决于我们赋予这些数据源多大的采样权重。

实际系统还需要区分按文档采样还是按 Token 采样，并处理文档长度、序列打包等细节。

### 11.2 Mixture 为什么如此重要？

假设我们已经有一个非常庞大的网页语料库。

但其中代码数据占比很低。

如果不对数据进行额外混合，模型可能只会接触到有限的代码训练信号。

因此，我们可以从经过独立清洗的代码数据集中额外采样，提高模型学习代码的机会。

这并不是在说“代码一定比网页更重要”。

而是：

**不同的模型目标，需要不同的数据分布设计。**

The Pile、Dolma 等公开语料都体现了通过组合不同数据来源来构建语言模型预训练数据集的思想。[6][7]

### 11.3 Mixture 与 Dedup 有什么联系？

这是两个非常值得放在一起理解的步骤。

Dedup 主要解决：

> 某些内容是否因为被意外重复收集，而在训练中占据过高权重？

Mixture 主要解决：

> 我们希望不同类型的数据主动获得多大的训练权重？

前者主要减少无意产生的分布偏差。

后者主要设计有意选择的训练分布。

因此，可以把二者理解为：

**Dedup 是减少意外的重复权重，Mixture 是设计明确的数据采样权重。**

这也解释了为什么数据处理绝不是简单地“删得越多越好”。

## 十二、完整案例：假如让我设计一个英文预训练语料库

为了检验自己是否真的理解这些知识，我尝试设计一个简化的场景。

假设现在需要为一个英文技术助手构建预训练数据。

我们从互联网抓取到以下候选文档：

| 文档 | 内容描述            | 可能需要的处理  |
| -- | --------------- | -------- |
| A  | 一篇英文机器学习教程      | 保留       |
| B  | A 的转载版本，仅修改了页脚  | 近似去重     |
| C  | 充满广告和重复关键词的网页   | 质量过滤     |
| D  | 一篇原创中文科普文章      | 根据语言目标决定 |
| E  | 英文技术文章中包含私人联系方式 | 隐私脱敏     |
| F  | 已公开的数学测试集题目与答案  | 评测去污染    |
| G  | 一篇结构完整的英文技术博客   | 保留       |

现在按照流水线逐步处理。

### 第一步：Crawl

收集候选网页。

保存网页内容及必要的来源元数据。

### 第二步：Text Extraction

解析 HTML，提取正文。

尽量删除无关的导航栏、广告模板和重复页脚。

### 第三步：Language Filter

因为目标是英文语料，文档 D 可能不会进入这条英文数据流。

但这并不意味着它质量差。

如果需要构建多语言模型，可以把它加入相应语言的数据池。

### 第四步：Quality Filter

文档 C 的广告内容高度重复，信息密度较低，因此可能被移除。

### 第五步：Safety / Filtering

检查文档 E 是否包含需要保护的个人信息。

如果正文具有价值，可以考虑在符合相关要求的情况下进行脱敏，而不是直接删除整篇文章。

### 第六步：Dedup

文档 B 和 A 的主体内容高度相似。

可以将它们识别为重复候选，并依据去重策略选择保留内容。

### 第七步：Decontamination

如果文档 F 命中了我们预先确定需要保护的评测集，就需要移除或隔离相关内容。

### 第八步：Tokenize 与 Mixture

对剩余文本进行 Tokenization。

之后根据训练目标，决定如何与经过独立清洗的代码、图书或其他数据源进行混合采样。

最终得到适合模型训练的数据流。

这个案例让我理解到：

**数据处理不是用一个统一的“好坏标准”筛选所有文档，而是针对不同风险和训练目标，执行不同性质的处理。**

有的文档需要删除，有的需要去重，有的需要脱敏，有的需要转移到其他数据池。

只有把这些差异分清楚，才能真正理解预训练数据工程。

## 十三、进一步思考：为什么删掉数据，模型反而可能变得更好？

到这里，我们终于可以回答一个看似矛盾的问题：

**大模型不是需要更多数据吗？为什么数据过滤和去重反而可能提升模型效果？**

我认为应该从三个角度理解。

### 13.1 数据量不等于有效信息量

假设数据集中存在大量重复网页。

虽然它们让数据集的规模变得更大，但并没有带来同等程度的新信息。

模型反复看到相同内容，不等于模型持续获得新的知识。

因此：

> 更多的原始 Token，并不必然意味着更多有效的训练信号。

### 13.2 训练计算资源是有限的

实际训练中，计算资源和 Token 预算通常存在约束。

如果大量预算被重复和低价值内容消耗，就可能减少模型接触其他有效文本的机会。

通过合理过滤和去重，我们有机会在同样的训练预算下，提高数据的有效性和多样性。

这就是数据效率（Data Efficiency）的重要意义。

### 13.3 数据质量与多样性需要平衡

如果只追求高质量过滤，可能会删除有价值但风格特殊的文本。

如果只追求最大程度去重，也可能降低语料的表达多样性。

如果只追求数据量，又会受到大量噪声和重复内容的影响。

因此，训练语料设计实际上需要权衡：

* Quality：质量；
* Diversity：多样性；
* Coverage：覆盖范围；
* Quantity：数据规模；
* Risk：风险；
* Efficiency：训练效率。

这几个目标之间，并不存在永远成立的简单排序。

最终还是需要通过对照实验和下游评测来验证具体的数据处理选择。

这也是 FineWeb 等工作强调数据处理消融实验（Ablation Study）的重要原因。[5]

## 十四、容易混淆的几个概念

### Q1：Raw Web Data 真的完全不能直接训练吗？

不是。

经过必要的解析和 Tokenization，模型可以在未充分清洗的网页文本上进行训练。

但从数据质量、训练效率、隐私风险和评测可信度等方面来看，直接使用未经充分处理的互联网数据通常存在明显问题。

因此，“不能直接训练”更准确的意思是：

**不应该不加判断地把原始互联网数据视为已经准备好的高质量训练语料。**

### Q2：Quality Filter 和 Safety Filter 是不是一回事？

不是。

Quality 更关注文本是否具有训练价值。

Safety 更关注内容是否存在需要管理的风险。

一篇文章可能质量很高，却包含隐私信息。

一篇文章也可能没有明显安全风险，但内容充满乱码和重复广告。

### Q3：Dedup 和 Decontamination 是不是一回事？

不是。

Dedup 主要处理训练语料内部的重复。

Decontamination 主要处理训练数据与评测数据之间的泄露或重叠。

两者可以使用相似的匹配技术，但主要目标不同。

### Q4：去重是否意味着所有内容只能出现一次？

不是。

实际系统可能基于文档、段落或者子串进行不同粒度的去重。

而且，对于高价值的数据源，也可能在 Mixture 阶段有意提高采样权重。

因此，需要区分：

* 无意产生的数据重复；
* 经过设计的重复采样。

它们具有不同的工程意义。

### Q5：只要数据清洗足够严格，就一定能训练出更好的模型吗？

不一定。

严格过滤可能提高某些指标，但也可能损失数据多样性、削弱特定语言或专业领域的覆盖。

优秀的数据处理方案需要通过实验验证，而不是只依赖过滤规则的直觉。

## 十五、如果在技术面试中被问到：为什么 Raw Web Data 不能直接用于 LLM 预训练？

我会这样回答：

> 原始互联网数据虽然规模大、覆盖广，但存在大量噪声、重复内容、语言分布失衡、隐私信息以及评测数据泄露等问题。
>
> 由于大语言模型预训练主要通过预测 Token 来学习数据中的统计规律，因此原始语料的分布会影响模型的训练目标。如果某些文本因为转载被大量重复收集，它们就可能在训练中获得不合理的相对权重，增加记忆化风险并浪费训练预算。
>
> 因此，通常需要构建一套预训练数据处理流水线，包括数据采集、语言过滤、质量过滤、安全处理、去重、评测去污染、Tokenization 和数据混合。
>
> 其中，Dedup 不只是减少数据规模，更重要的是减少重复内容对训练分布的扭曲；Decontamination 用于降低评测泄露；Mixture 则通过控制不同数据源的采样权重，使训练数据分布更加符合模型目标。
>
> 最终，预训练数据构建的目标并不是单纯追求更多 Token，而是在有限计算预算下，兼顾数据质量、多样性、覆盖范围、效率和风险。

## 十六、总结：Day 18 我真正学到了什么？

通过今天的学习，我对大模型预训练数据建立了一个更加完整的认识。

最开始，我以为预训练数据准备就是：

“从互联网下载很多文本，清洗一下，然后 Tokenize。”

但真正理解之后，我发现预训练数据工程的核心是：

**设计模型实际学习的数据分布。**

可以将今天的知识归纳为以下几个层次。

**第一，互联网只是数据来源，不等于训练数据集。**

Common Crawl 这样的项目能够提供大规模原始网页材料，但我们仍然需要进行正文提取、过滤、去重和其他数据治理工作。

**第二，模型的训练目标决定了数据分布的重要性。**

语言模型不会天然识别某段文本的重要性。

重复、噪声和数据来源偏差，都可能影响模型在训练中的学习重点。

**第三，数据去重不是简单的存储优化。**

Dedup 的重要作用是减少无意重复带来的训练分布偏差，并在适当条件下改善训练效率、降低记忆化程度。

**第四，数据质量、安全性和评估可信度是不同的问题。**

Quality Filter、Safety Filter 和 Decontamination 各自解决不同的风险，不能简单互相替代。

**第五，Mixture 决定最终的训练数据分布。**

经过清洗的数据仍然需要根据模型目标合理采样。

不同的数据组合，可能塑造出不同的模型能力侧重。

所以，今天最值得记住的一句话是：

> **Data curation is not just about cleaning data. It is about shaping what the model learns.**
>
> 数据整理不仅是在清洗数据，更是在塑造模型能够从数据中学习到什么。

这也是我开始理解 Data-Centric AI（以数据为中心的人工智能）的一个重要起点。

模型架构和训练算法固然重要，但决定模型性能的，不只是模型本身，还包括我们为它准备了怎样的数据。
