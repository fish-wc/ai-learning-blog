train.py 是整个 SFT 流程的**执行引擎**，它把数据集、模型、优化器、学习率策略串联成完整的训练闭环。核心可以拆成 **7 大核心成分**，按执行顺序依次是：参数配置、模型与分词器加载、数据加载管道、优化器、学习率调度器、训练主循环、模型保存。下面逐个拆解作用与原理。

---

### 1. 参数配置模块（parse_args）
**代码位置**：`parse_args()` 函数
**核心作用**：集中管理所有训练超参数与路径配置，通过命令行即可调整，无需修改代码。
**基本原理**：
基于 argparse 实现命令行参数解析，把训练相关的所有可变量全部外置。关键参数分为几类：
- 模型与数据：模型路径、训练数据路径、最大序列长度、样本数量
- 训练超参：微批次大小（`micro_batch_size`）、梯度累积步数、学习率、权重衰减、预热步数、训练轮数、梯度裁剪阈值
- 精度与输出：是否启用 bf16、模型保存目录、日志打印频率

其中最关键的设计是 **`micro_batch_size + grad_accum_steps` 的拆分**：把“等效批次大小”拆成“单卡单次批次”和“梯度累积步数”，适配单卡显存限制。

---

### 2. 模型与分词器加载
**代码位置**：main() 中 `AutoTokenizer` / `AutoModelForCausalLM` 部分
**核心作用**：加载预训练基座模型和对应的分词器，初始化训练的主体。
**基本原理**：
- **AutoModelForCausalLM**：HuggingFace 的通用因果语言模型加载接口，自动根据模型配置加载对应结构的模型。SFT 是在预训练模型基础上微调，所以必须加载完整的预训练权重作为起点。
- **bf16 半精度**：以 bfloat16 精度加载模型权重，相比 float32 显存占用减半，同时保留足够的数值精度，避免 fp16 常见的梯度下溢问题；配合 autocast 在训练中动态切换精度。
- **model.train()**：将模型切换到训练模式，启用 Dropout、LayerNorm 等训练专属逻辑；推理时用 `model.eval()` 关闭这些。
- **trust_remote_code=True**：允许加载模型仓库中的自定义模型代码，适配非标准模型结构。

---

### 3. 数据加载管道（Dataset + DataLoader + Collator）
**代码位置**：`SFTDataset` + `make_collator` + `DataLoader`
**核心作用**：把磁盘上的 parquet 数据，转换成可迭代的、批量的 GPU 张量，持续喂给训练循环。
**基本原理**：
- **SFTDataset**：继承 PyTorch Dataset，负责单条样本的读取、token 化、labels 掩码构造（具体逻辑在 dataset.py 中），按索引返回单条样本。
- **make_collator**：自定义批处理函数，把变长的单条样本右填充到同一长度，同时生成 attention_mask；labels 填充 -100，保证填充位不参与损失计算。
- **DataLoader**：PyTorch 标准数据加载器，负责：
  - `shuffle=True`：每个 epoch 打乱数据顺序，避免模型记住数据顺序，提升泛化性
  - `num_workers=2`：用多进程预加载数据，避免 CPU 数据处理成为训练瓶颈
  - `drop_last=True`：丢弃最后一个不足一个批次的样本，保证梯度累积的步数对齐，避免最后一步梯度不准

---

### 4. 优化器（AdamW）
**代码位置**：`torch.optim.AdamW(...)`
**核心作用**：根据反向传播得到的梯度，按照特定规则更新模型参数，最小化损失。
**基本原理**：
AdamW 是目前大模型微调的标准优化器，在 Adam 基础上加入了正确的权重衰减实现：
- **Adam 核心**：维护一阶矩（动量，平滑梯度方向）和二阶矩（自适应学习率，根据参数梯度大小调整更新幅度），让参数更新更平稳。`betas=(0.9, 0.999)` 是一阶、二阶矩的衰减系数，属于通用最优配置。
- **权重衰减（Weight Decay）**：在参数更新时，对权重本身施加小幅衰减（乘以一个小于1的系数），等价于 L2 正则化，防止模型过拟合，提升泛化能力。
- SFT 场景下用较小的学习率（通常 1e-5 ~ 1e-4），因为预训练模型已经收敛，只需要小幅度调整参数来对齐对话格式。

---

### 5. 学习率调度器（余弦退火 + 预热）
**代码位置**：`get_cosine_schedule_with_warmup(...)`
**核心作用**：训练过程中动态调整学习率，让训练初期更稳定、后期收敛更充分。
**基本原理**：
调度器分为两个阶段：
1. **预热阶段（Warmup）**：训练前 N 步，学习率从 0 线性上升到设定的目标学习率。
   - 原理：预训练模型初始参数已经很稳定，如果一开始就用大学习率，容易造成参数剧烈震荡，破坏预训练学到的知识；预热逐步提升学习率，让模型平稳进入微调状态。
2. **余弦退火阶段**：预热结束后，学习率按照余弦函数曲线从最大值逐步下降到接近 0。
   - 原理：训练前期参数偏离大，用较大学习率快速收敛；训练后期参数接近最优，用小学习率精细调整，帮助模型收敛到更好的局部最优点。

总训练步数的计算：`每epoch步数 = 总batch数 / 梯度累积步数`，`总步数 = 每epoch步数 × epochs`，调度器按照总步数规划学习率变化。

---

### 6. 训练主循环（最核心的执行逻辑）
**代码位置**：双层 for 循环（epoch + micro batch）
**核心作用**：完成“前向算损失 → 反向算梯度 → 累积/裁剪 → 更新参数”的完整迭代，是 SFT 训练的核心闭环。
这部分可以再拆成 6 个关键子环节：

#### （1）自动混合精度（torch.autocast）
**作用**：在保证训练精度的前提下，降低显存占用，提升计算速度。
**原理**：前向传播时，自动将矩阵乘法、注意力等计算密集型操作切换到 bf16 精度，而参数、梯度等关键状态保持 float32 精度。既享受到半精度的速度和显存优势，又避免了精度损失导致的训练不稳定。

#### （2）前向传播与自动损失计算
**作用**：输入批量数据，模型计算预测结果，并直接输出损失值。
**原理**：
当给模型传入 `labels` 参数时，HuggingFace 因果语言模型内部会自动完成两步关键操作：
1. **标签左移对齐**：把 labels 整体左移一位，和模型输出的 logits 对应——因为自回归模型是“用第 i 个 token 预测第 i+1 个 token”，所以标签需要错位一位。
2. **交叉熵损失计算**：使用 CrossEntropyLoss 计算预测与真实标签的损失，并且自动忽略 labels 中值为 -100 的位置（`ignore_index=-100`）。

这就是 SFT 损失的核心：**只在 assistant 回答的 token 上计算 next-token 预测损失**，用户提问和填充位都被 -100 掩码跳过。

> 代码中 `use_cache=False`：训练时不需要 KV 缓存（KV 缓存是推理时加速生成用的），关闭可以节省显存。

#### （3）梯度累积（Gradient Accumulation）
**作用**：在单卡显存有限的情况下，用小批次模拟大批次的训练效果。
**原理**：
正常大批次训练是“一次前向反向 → 更新参数”；梯度累积是把一次大批次拆成多次微批次：
- 每次微批次反向传播后，梯度会累加到参数的 grad 属性中（PyTorch 默认 backward 是累加梯度）
- 损失先除以 `grad_accum_steps`，保证多次累积后的梯度总和与大批次的梯度数学等价
- 累积够指定步数后，再统一执行参数更新

等效批次大小公式：`等效 batch_size = micro_batch_size × grad_accum_steps`

#### （4）反向传播（loss.backward()）
**作用**：根据损失值，通过链式法则逐层计算每个参数的梯度。
**原理**：
从输出层的损失开始，反向沿着计算图逐层传播，利用链式求导法则计算每个可训练参数对损失的梯度，结果存储在每个参数的 `.grad` 属性中，等待优化器更新。

#### （5）梯度裁剪（clip_grad_norm_）
**作用**：防止梯度爆炸，稳定训练过程。
**原理**：
计算所有参数梯度的全局 L2 范数，如果范数超过设定的阈值 `max_grad_norm`（这里是 1.0），就把所有梯度按比例缩小，使得全局范数等于阈值。SFT 中偶尔会出现异常大梯度，裁剪可以避免参数更新幅度过大，防止 loss 飙升。

#### （6）参数更新与梯度清零
**作用**：用累积好的梯度更新模型参数，然后重置梯度状态。
**原理**：
- `optimizer.step()`：根据梯度和优化器规则，更新所有可训练参数的值
- `lr_scheduler.step()`：推进学习率调度，更新当前步的学习率
- `optimizer.zero_grad()`：清空所有参数的梯度，避免下一轮累积时叠加旧梯度

### 7. 模型保存模块
**代码位置**：`model.save_pretrained(...)` + `tokenizer.save_pretrained(...)`
**核心作用**：将训练完成的模型权重和分词器持久化到磁盘，用于后续推理或继续训练。
**基本原理**：
- `save_pretrained`：保存为 HuggingFace 标准格式，包含模型权重、配置文件，后续可以直接用 `from_pretrained` 加载。
- `safe_serialization=True`：使用 safetensors 格式保存权重，比传统 bin 格式更安全（无执行代码风险）、加载速度更快。
- 最小实现中**只保存模型权重，不保存优化器和调度器状态**，目的是节省磁盘空间；完整实现会保存全部状态，用于断点续训。

---

### 整体训练闭环梳理
加载数据 → 加载模型 → 初始化优化器和调度器 → 遍历每个epoch → 遍历每个微批次 → 前向算损失 → 反向算梯度 → 累积够步数 → 裁剪梯度 → 更新参数 → 更新学习率 → 清零梯度 → 循环直到结束 → 保存模型。
