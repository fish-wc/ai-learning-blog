# 中间激活（intermediate activations）
一句话：**模型前向计算时，每一层输出的张量，就是中间激活。反向求梯度的时候，需要用到这些值，所以默认会全部保存在显存里。**

## 举个最简单例子：单层Transformer块
```
输入 hidden_states → 多头注意力 → 中间A → MLP层 → 中间B → 输出hidden_states
```
- 前向：输入一路算过去，算出最终loss。
- **默认模式（不开启梯度检查点）**：
  为了反向传播求梯度，GPU必须把**中间A、中间B**这些每一层的输出张量全部留在显存。
  这些 `中间A、中间B` 就是**中间激活**。
> 模型越大、序列越长，中间激活张量越多，显存占用会急剧上升，很容易OOM。

## 梯度检查点 gradient checkpointing 的原理
**用计算换显存**：
1. 前向的时候：**不保存中间激活**，直接丢弃，省下大量显存；
2. 反向传播的时候：**重新跑一遍前向，临时算出需要的中间激活**，再继续求梯度。

代价：训练速度变慢（多跑一遍前向）；收益：大幅降低显存占用，能塞更大模型/更长序列。
> 数学上等价，最终loss和梯度结果不变，只是多了一次重算。

## 放到VERL大模型训练场景理解
Transformer每一层：注意力输出、MLP的激活（gelu/swish输出）全部都是中间激活。
- 3B模型，序列很长时，所有层的中间激活叠加起来，显存开销甚至比模型权重本身还要大；
- `enable_gradient_checkpointing: true` 开启后，不再缓存这些中间激活，反向时重算，解决显存吃紧问题。

## 容易混淆点区分
- ✅ **模型权重（parameter）**：w、b，可训练参数，训练全程保存在显存，不会被梯度检查点丢弃；
- ✅ **中间激活（activation）**：前向过程每层临时输出，**梯度检查点主要省的就是这部分显存**。

### 极简总结
> 中间激活 = 前向推理过程中每一层算出来的临时张量；
> 正常训练全部存显存；梯度检查点丢掉它们，反向时重新计算，牺牲少量速度换显存。
