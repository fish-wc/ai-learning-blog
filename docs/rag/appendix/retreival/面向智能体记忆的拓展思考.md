# 4. 面向智能体长期记忆的拓展思考

传统 RAG 系统通常面向相对稳定的外部知识库：

```text
User Query
    |
    v
Retrieval
    |
    v
Rerank
    |
    v
LLM Generation
```

而在 Agent（智能体）系统中，Memory 模块可以被理解为一种动态 RAG。

与传统 RAG 不同，智能体记忆具有以下特点：

1. **记忆持续增长**：智能体在任务执行、用户交互与环境感知过程中，不断产生新的记忆片段；
2. **查询动态生成**：Memory Query 不一定来自用户，而可能由智能体内部推理过程自动生成；
3. **查询分布持续变化**：随着任务、环境和用户状态的变化，记忆检索需求也会发生偏移；
4. **记忆具有时效性**：新记忆可能覆盖旧记忆，部分历史信息会逐渐失效；
5. **记忆相关性具有上下文依赖**：语义相似并不意味着当前任务需要使用该记忆。

因此，智能体长期记忆不仅需要解决向量检索问题，还需要考虑：

- 动态索引维护；
- 历史记忆召回；
- 记忆相关性重排；
- 时间与实体一致性；
- 记忆更新和失效管理。

---

## 4.1 Retrieval 层：动态记忆索引

传统 RAG 的 Document 通常来自固定的数据集，而智能体 Memory 会持续新增。

假设在时刻 $t$，智能体的记忆集合为：

$$
\mathcal M_t=\{m_1,m_2,\dots,m_n\}
$$

随着智能体执行新的任务，会产生新的记忆：

$$
\Delta \mathcal M_t
$$

记忆集合随之更新：

$$
\mathcal M_{t+1}
=
\mathcal M_t\cup\Delta\mathcal M_t
$$

这里暂时只考虑新增记忆，不包含修改和删除。

这意味着 ANN 索引需要支持频繁的增量插入。

### HNSW 更适合动态记忆场景

HNSW 的增量插入机制使其在动态 Memory 系统中具有明显优势。

新记忆产生后：

```text
New Memory
     |
     v
Embedding Model
     |
     v
Memory Vector
     |
     v
HNSW Incremental Insert
     |
     v
Updated Memory Index
```

系统不必在每次添加记忆后重新构建整个索引。

相比之下，IVF 虽然同样支持在训练完成后追加向量，但当新记忆的分布与原始训练数据发生明显偏移时，已有聚类中心可能不再适合当前数据分布。

因此，在记忆持续增长、更新频繁的场景中，HNSW 通常是值得优先评估的索引结构。

不过：

**HNSW 支持增量插入，不代表完全不需要索引维护。**

随着记忆数量增加、旧记忆删除以及数据分布变化，系统仍可能需要：

- 清理失效节点；
- 优化图结构；
- 控制索引内存；
- 定期压缩或重建索引。

## 4.2 Retrieval 层：混合检索（Hybrid Retrieval）

纯 Dense Embedding 检索擅长捕捉语义相似性，但在智能体记忆场景中，仅依赖向量相似度可能存在不足。

例如：

```text
Query:
用户上次提到的项目代号 Apollo 是什么？

Memory A:
用户正在推进 Apollo 项目。

Memory B:
用户最近正在开发新的软件系统。

Memory C:
用户曾讨论过一个航天相关项目。
```

Dense Embedding 可能认为 Memory B 和 Memory C 具有较高的语义相似性。

但从精确实体匹配角度看，Memory A 更重要。

因此，智能体记忆系统可以使用：

**BM25 + Dense Embedding 混合检索。**

两者具有不同优势。

| 检索方式 | 核心能力 | 适合场景 |
|---|---|---|
| BM25 | 词项匹配与关键词相关性 | 人名、项目名、编号、专有名词 |
| Dense Retrieval | 语义相似性检索 | 语义改写、模糊表达、概念关联 |
| Hybrid Retrieval | 综合词项与语义信号 | 复杂记忆查询 |

典型流程：

```text
                    Memory Query
                         |
             +-----------+-----------+
             |                       |
             v                       v
       BM25 Retrieval          Dense Retrieval
             |                       |
             v                       v
       Sparse Top-K             ANN Top-K
             |                       |
             +-----------+-----------+
                         |
                         v
                  Result Fusion
                         |
                         v
                  Candidate Memory
                         |
                         v
                  Cross-Encoder
                         |
                         v
                  Final Top-N
```

混合检索结果可以通过 RRF（Reciprocal Rank Fusion）等方法进行融合。

例如：

$$
\operatorname{RRF}(d)
=
\sum_{r\in R}
\frac{1}{k+\operatorname{rank}_r(d)}
$$

其中：

- $R$：不同检索器的集合；
- $\operatorname{rank}_r(d)$：文档 $d$ 在检索器 $r$ 中的排名；
- $k$：平滑常数，用于控制不同排名之间的分数差异。

RRF 不要求 BM25 与 Dense Retrieval 的原始分数处于同一数值范围，因此适合融合异构检索结果。

对于智能体 Memory：

> BM25 负责保留关键实体与词项匹配能力，Dense Retrieval 负责捕获语义相关性，两者结合可以减少单一检索方式造成的遗漏。

## 4.3 Rerank 层：从语义相关性到记忆证据选择

在智能体记忆系统中，Rerank 的目标不仅是判断两段文本是否语义相关，还需要判断：

**这段历史记忆是否能够为当前任务提供有效证据？**

例如：

```text
Current Query:
用户现在更偏好 Python 还是 Java？

Memory A:
用户在一年前提到喜欢 Java。

Memory B:
用户昨天表示近期主要使用 Python。

Memory C:
用户曾经学习过 Java 和 Python。
```

从语义角度看，三段记忆都可能与 Query 相关。

但如果目标是判断用户当前的偏好，那么时间、上下文以及事实有效性就非常重要。

因此，Agent Memory Rerank 可以综合多个信号：

- Semantic Relevance：语义相关性；
- Temporal Relevance：时间相关性；
- Entity Consistency：实体一致性；
- Task Relevance：当前任务相关性；
- Evidence Quality：证据质量。

一种可选的工程设计是构造组合评分函数：

$$
S(q,m)
=
\alpha S_{\text{semantic}}(q,m)
+
\beta S_{\text{temporal}}(q,m)
+
\gamma S_{\text{task}}(q,m)
$$

其中：

$$
\alpha,\beta,\gamma \geq 0
$$

且可以设置：

$$
\alpha+\beta+\gamma=1
$$

需要注意：

这只是示意性的工程评分框架，并非 Cross-Encoder 的标准模型结构。

如果不同信号的原始分数尺度不同，则需要进行归一化或校准后再融合。

### Cross-Encoder 与 LLM Reranker

对于普通语义相关性判断，Cross-Encoder 往往是较好的选择。

但在一些复杂记忆查询中，仅依赖相关性分数可能仍然不够。

例如：

- 两段记忆是否存在事实矛盾；
- 新记忆是否覆盖了旧记忆；
- 某段记忆是否只在特定时间条件下有效；
- 多段记忆是否需要联合推理才能回答问题。

这时可以考虑使用 LLM Reranker。

例如：

```text
Memory Candidates
       |
       v
LLM Relevance Evaluation
       |
       v
Evidence Comparison
       |
       v
Memory Selection
```

LLM 可以对候选记忆进行更复杂的语义与逻辑判断。

但其局限也很明显：

**推理成本通常更高。**

因此，比较合理的实践是：

1. 使用 ANN 检索大量候选；
2. 使用 Cross-Encoder 执行第一轮精排；
3. 仅对少量复杂候选使用 LLM 进行进一步判断。

这种多阶段设计可以在检索成本与复杂推理能力之间进行权衡。

## 4.4 长期记忆系统的核心工程权衡

随着智能体持续运行，Memory 数量可能不断增加。

假设：

$$
|\mathcal M_t| \rightarrow \infty
$$

即记忆集合持续膨胀。

此时系统需要考虑的不再只是 Recall 和 Precision，还包括：

- 索引构建成本；
- 向量存储成本；
- ANN 查询延迟；
- Rerank 推理成本；
- 记忆删除和更新成本；
- 最终 LLM Context Window 的容量限制。

不同阶段存在不同的性能瓶颈。

| 阶段 | 主要瓶颈 | 典型优化方向 |
|---|---|---|
| Memory Embedding | 向量编码成本 | 批量编码、缓存 |
| ANN Index | 内存与索引维护 | HNSW 参数优化、向量量化 |
| Retrieval | Recall 与查询延迟 | 调整 ANN 搜索参数、混合检索 |
| Rerank | 模型推理成本 | 限制候选数量、批处理 |
| Context Assembly | Token 容量与信息冗余 | 去重、压缩、证据筛选 |

其中，一个重要原则是：

**不能只优化单个阶段，而应评估整个 Memory Retrieval Pipeline 的端到端效果。**

例如：

增大 Retrieval Top-K，通常可以提高候选覆盖率。

但同时也意味着：

- Cross-Encoder 需要处理更多候选；
- Rerank 推理开销增加；
- 端到端检索延迟可能上升。

因此需要在：

$$
\operatorname{Recall@K}
$$

与：

$$
\operatorname{Latency}
$$

以及：

$$
\operatorname{RerankCost}
$$

之间找到合理的平衡。

---

## 4.5 总结：两阶段 RAG 在 Agent Memory 中的价值

Retrieval + Rerank 的核心并不是简单地串联两个模型，而是将大规模搜索与精细相关性判断进行解耦。

从系统设计角度看：

**Retrieval 解决候选覆盖问题。**

通过 Bi-Encoder 与 ANN，快速从海量记忆中筛选可能相关的内容。

**Rerank 解决候选排序问题。**

通过 Cross-Encoder 或其他更强的相关性模型，提高最终记忆证据的匹配质量。

在智能体长期记忆场景中，该架构可以进一步延伸为：

```text
             Agent Internal Query
                      |
                      v
                Query Encoding
                      |
                      v
             Hybrid Retrieval
                      |
            +---------+---------+
            |                   |
            v                   v
       Dense ANN              BM25
            |                   |
            +---------+---------+
                      |
                      v
                Result Fusion
                      |
                      v
              Top-K Memories
                      |
                      v
             Cross-Encoder Rerank
                      |
                      v
              Top-N Memories
                      |
                      v
            Memory Context Assembly
                      |
                      v
                 Agent LLM
                      |
                      v
                Task Execution
```

需要强调：

**Rerank 无法修复 Retrieval 已经丢失的相关记忆。**

因此，对整个系统而言：

> Retrieval 决定哪些记忆有机会进入上下文；Rerank 决定哪些候选记忆应该被优先使用；LLM 则基于最终选择的证据完成推理与生成。

随着 Agent Memory 规模持续扩大，ANN 索引效率、动态维护能力、候选重排质量与上下文管理，将共同决定长期记忆系统的实际表现。
