# 04 · 从零启动新项目手册（核心技术栈 + 启动清单）

> 场景假设：你要在一个新业务/新 Agent 产品上，从零建立"评测结果分析"这个技术环节。本篇是可执行的启动手册。

## 1. 核心技术栈清单

| # | 技术栈 | 具体能力 | 学习来源 |
|---|---|---|---|
| 1 | **评测数据工程** | CSV/JSON 大字段解析（`csv.field_size_limit`）、统一 case 模型适配、逐 case 证据提取、可审计中间产物 | 02 篇 §1、`stats_pipeline.py` |
| 2 | **指标口径设计** | 三口径可用率、失败/未评分/中断分桶、分母规则、同尺重算、加和闭合校验 | 01 篇 §2、03 篇 §1 |
| 3 | **LLM-as-judge 特性应对** | 判词结构化提取（reasoning/维度分/violations）、判罚漂移检测（同 run 双检 + 跨 run 反转）、输出退化/CoT 泄漏识别、评测器版本追踪 | 02 篇 §5、03 篇 §2-3 |
| 4 | **问题分类学** | 一级归因优先级（防冤枉）、二级分类规则锚定、互斥规则、severity 取主分类、taxonomy 持续校准 | 02 篇 §3-4 |
| 5 | **case 级验证** | violations 快速路径 vs 回退分类、自动验证 + 手动 checklist、证据摘要格式、置信度分档 | 02 篇 §5 |
| 6 | **多智能体编排** | 逐 case fan-out、深度分析并行、对抗复核、label 聚合、schema 约束结构化输出 | 03 篇 §2.1（战例）+ skill「多智能体编排建议」（可迁移设计件） |
| 7 | **改动归因**（可选） | 变化预览解析、失败簇×改动映射、机制链+反证+置信度、验证计划设计（revert/AB/交叉重评） | 03 篇 §6 |
| 8 | **产物工程** | 报告结构设计（读者倒推）、多 sheet 明细表、追溯闭环、一致性校验 | 03 篇 §4 |
| 9 | **交付与协作** | 飞书文档/表格发布、产物互链、Owner 归属、评审动线 | 01 篇 §3、03 篇 §5 |

不需要每项都精通：#1#2#4#5 是吃饭的本事，#3#6 是效率放大器，#7#8#9 决定产出能不能被组织消化。

## 2. 启动清单（按周推进）

### 阶段 0：搞清对象与干系人（第 1 周前半）

- [ ] 被测 Agent 的业务边界是什么？有哪些技能/工具/域？
- [ ] 评测集有哪些？case 怎么定义"期望"（标注/规则/参考答案）？
- [ ] 评测器是谁产出的？几个？分数制与阈值？判词里有哪些规则锚点？
- [ ] 产出给谁看？门禁规则是什么？谁是各模块 Owner？

### 阶段 1：口径与数据底座（第 1 周）

- [ ] 用 `analyze-xiaoaiclaw-eval-results` 的适配思路建立统一 case 模型（或直接复用其 `input_adapter.py`）；
- [ ] 定义分数桶（已评分/未评分/失败/中断）与三口径指标，写成文档**固化**；
- [ ] 写确定性统计脚本（可参考 `compare-xiaoaiclaw-eval-runs/scripts/stats_pipeline.py`），输出校验锚点；
- [ ] 逐 case 证据文件落盘机制。

### 阶段 2：分类体系（第 2 周）

- [ ] **先建业务规则目录（分类体系的锚定源）**：通读被测 Agent 的 SKILL.md 与 references/（工具规格/准入判定/流程/话术规范），把可校验的约束逐条抽成规则表——每条给稳定 slug、来源文件+段、一句话约束（引原文关键词）、它违反时对应的分类 ID；规则原文以产品仓库为准，目录只做索引不复述大段原文；
- [ ] 再从真实 badcase 里归纳二级分类（每个分类回答：锚定哪条规则 slug？轨迹/判词信号是什么？典型表现？——没有规则可锚的分类要问"这是真问题还是我拍的名字"）；
- [ ] 定一级归因优先级（照搬 02 篇的 8 类优先级即可）；
- [ ] 定互斥规则与 severity 排序，用 20-50 个真实 case 手工校准；
- [ ] 建 golden fixtures（每分类 2-3 个标注样例）供回归。

### 阶段 3：单 run 分析流水线（第 2-3 周）

- [ ] 跑通"统计→分类→归因→验证→报告"全链路；
- [ ] 报告含：边界声明、指标（带分母）、分类分布（主分类+多标签）、代表 case（引判词原文）、评测器健康检查、改进建议（带 Owner）；
- [ ] 抽 10 个 case 人工复核分类质量。

### 阶段 4：跨 run 对比能力（第 3-4 周）

- [ ] 直接装配 `compare-xiaoaiclaw-eval-runs` 技能（`skills/` 目录下，配齐两个脚本）；
- [ ] 跑一次真实对比校准失败族分类（F1a~F4 的子类按你的业务改名）；
- [ ] 建立"翻转 case 审计"例行（每轮与上轮对比，跨阈值翻转自动进复核队列）；
- [ ] （可选）接入变化预览材料，跑通改动归因 + 验证计划。

### 阶段 5：运营化（持续）

- [ ] 口径与阈值写入平台指标管线，避免逐批事后重算；
- [ ] 分类体系版本化（每次校准记录"从哪批数据总结"），new_pattern 占比监控；
- [ ] 例行报告模板固化（三口径门禁 + 变化预览 + 组件归因 + Owner）；
- [ ] 评测器版本变更登记（workflow_id 级），换版即触发"同尺重算/交叉重评"。

## 3. 常见坑速查

| 坑 | 症状 | 解法 |
|---|---|---|
| 分母漂移 | 两次 run 可用率之差与逐 case 变化对不上 | 三口径并报 + 归因口径唯一 + 分母效应桥接 |
| 混合口径 | 引用外部报告数字后复算不一致 | 引用前复算两侧评测器名，同尺重算 |
| 失败当 0 分 | 可用率被链路失败率污染 | 失败单列桶，分子分母都不进 |
| 前缀匹配 case_id | 一个短 id 吞掉多个 case | 全值匹配，脚本里断言集合一致 |
| 信判词如信事实 | 归因翻车（判官漏看/退化） | 证据分级 + 交叉验证 + 判罚一致性双检 |
| 分类不互斥 | 合计对不上总数 | 互斥规则 + severity 取主分类 + 合计校验行 |
| 归因不闭合 | 三因素之和 ≠ 总变化 | 固定分母 + 桥接行 + 硬校验行 |
| 多智能体结果错位 | 聚合出脏数据 | 按 label 聚合 + 覆盖校验 |
| 外部叙事带偏 | 跟着"同窗嫌疑"归因 | 执行通道事实优先，机制不接壤不硬归 |
| 候选集不闭合 | 改动归因缺斤短两 | 标注时间边界，拉完整 commit range |

## 4. 工具与技能装配

```
~/.claude/skills/analyze-xiaoaiclaw-eval-results/   # 单 run 质量剖析（已存在）
skills/compare-xiaoaiclaw-eval-runs/                # 跨 run 对比 + 改动归因（本教程配套沉淀）
├── SKILL.md                    # 全流程指导（参数/口径/8 步/产物/红线/编排建议）
└── scripts/
    ├── stats_pipeline.py       # 确定性统计 + 逐 case 证据提取（已实测）
    └── build_case_workbook.py  # 8-sheet case 明细 Excel 生成（已实测）
```

跨 run 技能的标准调用参数：

```
基准目录：{DIR_A}｜对比目录：{DIR_B}｜唯一认定评测器：{EVALUATOR_NAME}｜可用阈值：{THRESHOLD}｜[变化预览文件：{DIR_DIFF}]
```

装配到 `~/.claude/skills/` 后即可用上述参数一句话触发全流程；提供 `DIR_DIFF` 时自动追加改动归因报告。

## 5. 出师标准（自查）

- [ ] 能不看文档说清"为什么可用率分母不是全量 case"的三个理由；
- [ ] 给一个非满分 case，能在 5 分钟内做出带证据的分类与一级归因，并说出置信度；
- [ ] 能解释 LLM judge 的三种不稳定形态（裁量漂移/输出退化/版本漂移）及各自的检测方法；
- [ ] 能独立设计一次跨 run 对比的口径方案，并让三因素归因加和闭合（含"未决"行与分母桥接）；
- [ ] 抽查报告里任意 3 条根因描述，每条都能说出证据等级（J/O/R）和原文出处；
- [ ] 写出的报告让研发负责人"打开就能安排动作"——自查判据：3 句话结论带口径名、每个失败类型有 case 清单入口（Excel sheet 名）、每条优化建议有责任侧和验证方式。
