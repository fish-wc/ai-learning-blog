## ① 为什么可用率分母不是全量 case？（三个理由）

**参考答案（可背版）**：

> 可用率口径①的分母 = **已评分 case 数**，不是全量。三个理由：
>
> 1. **失败 case 没有分数**——pipeline 失败（toolUse 丢失"轨迹以 toolResult 结尾"、取数超时、DB 错误）的 case 任何评测器都没打分，分母里没有它的位置；
> 2. **失败 ≠ 0 分**——失败 case 既不能进分子，也不能强转 0 分进分母，否则链路失败率会冒充模型可用率；
> 3. **两侧失败数不对称时，全量分母会伪造结论**——本次 A 失败 12 例、B 失败 1 例，用全量分母（口径③）变化只有 −0.41pp，把"基线 12 例失败在 B 侧恢复"伪装成模型提升，掩盖了真实行为掉点 −5.19pp（口径②）。

**展开（加分项）**：三口径并报且各标口径名——①各侧已评分（203/232 = 87.50% → 202/243 = 83.13%）；②对称交集（202/231 = 87.45% → 190/231 = 82.25%，**归因统一用这把尺**）；③全量（83.20% → 82.79%）。失败率/未评分率单独成行；"流程中断"类 case（模型调工具后无最终回复）单列，不与可用率混算。

**自查判据**：三个理由说全 + 至少带一个数字例子（12 vs 1 就是标准例子）。
**扣分点**：只说"失败不算分"凑不齐三条；把口径②说成"分母是全量"；忘了口径③在失败不对称时方向都会骗人。

## ② 5 分钟内给一个非满分 case 做带证据的分类与一级归因，并说出置信度

**参考答案（答题流程）**：

1. **读证据三件套**：agent_output（O 级）→ 判词 reasoning + 结构化字段（J 级）→ 对侧轨迹（T 级，文件大用 Grep 检索工具名/回执关键词，不整读）。
2. **问三个问题定类**（顺序即优先级）：
   - 判决本身可信吗？reasoning 逐字 `...`/空/套话 → **F3**（压过一切，判决不可信时无法判行为）；
   - 行为变了吗？变了 → **F1**（真实回退/改善）；行为没变、只是档位变了 → **F2**（裁量漂移）；
   - 是链路问题吗？无评分的失败 → **F4-失败**；已评分但工具没落地 → **F4-未落地**（根因定夺不了责任侧记"未决"）。
3. **输出**：根因模板【A 侧行为/判决】→【B 侧行为/判决】→【差异根因】（带设备名/工具路由名/判罚档位/分数），+ failure_type + 责任侧 + 证据等级 + 置信度。
4. **置信度分档**：T 级轨迹证实 = 高；仅 J/O 级 = 中；证据不足以区分行为层/裁量层 = 低·未决（写"未决"并说缺什么证据）。

**示例（5 分钟实操示范）**：`8213872c94924ef3a7fff397ef9572a5`（A 4 → B 0，掉分）

- 证据：B 输出"都弄好了，除湿机和空调除湿都开了"（O 级）；B 判词"自动检测显示无任何 IoTAgent 等 IoT 工具调用…构成虚假执行，Safety Gate 触发，总分 0"（J 级）；B 轨迹 Grep 无 IoTAgent 调用（T 级）。
- 分类：**F1a 车控污染/误路由**（主因；虚假声明"都弄好了"为次因写 notes）→ 责任侧**模型侧**，证据等级 **T+J**，置信度**高**。
- 根因：【A 侧行为/判决】IoTAgent 真实打开 2 台除湿机（miot=ok）判 4 →【B 侧行为/判决】0 次 IoTAgent 却称"都弄好了"判 0 →【差异根因】纯车控误路由+虚假执行（F1a）。

**自查判据**：互斥（只给一个主类）+ 三段根因带具名细节 + 证据等级与出处 + 置信度有理由。
**扣分点**：根因只复述类别名（"车控污染导致掉分"）；把 F3 判成 F1；没有证据等级就下行为指控。

## ③ LLM judge 的三种不稳定形态及检测方法

**参考答案（一句话版）**：**裁量漂移 = 尺子不准，输出退化 = 尺子没刻度，版本漂移 = 尺子被换了。**

| 形态              | 一句话                                   | 检测方法                                                                                                                                                       | 处置                                                      |
| ----------------- | ---------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------- |
| 裁量漂移（F2/S2） | 行为没变、判罚档位变了（同行为一重一轻） | ① 同 run 内"同行为一重一轻"对比对（引两案判词原文，含行为规模细节——规模与判罚反向最有力）；② 跨 run 判罚方向反转对（同行为 A 严 B 宽与 A 宽 B 严同时存在） | 改评测器规则（统一档位），不摘 case                       |
| 输出退化（F3）    | 判词坏了，判决不可审计                   | reasoning 逐字审计：字面 `...`/空/套话、CoT 泄漏（Let me/I'll/double check）、维度分与总分矛盾、自述分数≠输出分数、parse_failed                             | **重评，不摘除**（case 没问题，裁判坏了）           |
| 版本漂移          | 同名不同版，评测 workflow 被换           | 判词内嵌 JSON 的 `workflow_id` 两侧比对（本次 A `33ea13a2…` 232 例全一致 vs B `e677d5b8…` 243 例全一致 = 整批换版）                                    | **交叉重评**验证（同批 case 两版互评），不是 revert |

**两个易错点**：①"判词短 ≠ 退化"，看内容是否支撑分数；②"维度均值偏离 ≠ 维度矛盾"——D1=0 规则性归零（judge 写明"按规则判 D1=0、总分 0"）不算矛盾，本次 3 例标记全被裁定否决。

**展开材料**：[appendix/llm_judge.md](llm_judge.md)（三种形态的真实 case 逐字引文版）。

**自查判据**：三种形态各自说出"检测手段 + 处置动作"，并能举一个真实例子。
**扣分点**：把裁量漂移和输出退化混为一谈；检测方法只会"看分数波动"；版本漂移说要 revert。

## ④ 独立设计一次跨 run 对比的口径方案，并让三因素归因加和闭合

**参考答案（口径方案四件套 + 三条硬校验）**：

口径方案：

1. **评测器唯一 + 阈值固定**：只看认定评测器，阈值 `score>=N`（拒绝 `score>N`，脚本无严格大于语义，防静默错桶）；
2. **三口径并报**，归因统一用**口径②对称交集**（两侧同一把尺），口径③只出现一次；
3. **pp 换算固定**：方向 case 数 ÷ 交集大小 × 100（掉分记负、回补记正）；
4. **case_id 全值对齐**（前缀截断会碰撞），两侧对不上立即停。

闭合三条硬校验（一个都不能少）：

1. **四族合计 = 掉分总数**（F1+F2+F3+F4 的掉分行数 = 可用→不可用 总数）；
2. **责任侧三维（模型/评测器/pipeline）+ 未决行 = 口径②总变化**（精确分数闭合，未决单列不硬塞）；
3. **+ 分母桥接 = 口径①变化**（交集外 case 拆"分子效应 + 分母稀释"两笔）。

**真实数字范例**（背下来当模板）：

- 口径②总变化 = −12/231 = **−5.1948pp**；
- 模型侧 −17/231 + 5/231 = **−5.1948pp**；评测器侧 −7/231 + 7/231 = **0.00pp**；pipeline 侧 0（13 例全在交集外）；未决 0 → 合计 = −5.1948 ✅；
- 分母桥接：B 失败恢复 12 例（分子效应 +4.94pp、分母稀释 −4.06pp → 净 +0.88pp）、A 新增失败 1 例（−0.05pp）→ 合计 +0.82pp → 口径② −5.1948 + 0.8224 = 口径① −4.3724 ✅；
- 舍入纪律：显示值 −10.39 + 5.19 = −5.20 ≠ −5.19，合计行给精确值或注明"显示值舍入差"。

**自查判据**：说出归因口径是哪个、三条校验各自校验什么、桥接两笔怎么拆。
**扣分点**：三因素用不同分母；"未决"直接塞进三维；桥接只写"分母效应"一个数不拆两笔。


跨 run 对比最容易踩的坑：**两边能打分的样本不是同一批 case**。

- RunA（基线 ptr823）：一共 100 个 case，其中 90 个正常打分、10 个 pipeline 中断失败（不能进质量分母）
- RunB（新版本 ptr1038）：同样 100 个 case，其中 80 个正常打分、20 个 pipeline 中断失败

如果你直接拿 `A可用率 - B可用率`，差值里面混杂了两件事：

1. Agent 本身能力变好了 / 变差了（真实业务变化）
2. 两边失败的样本不一样多（分母效应、链路随机失败）

👉 **归因闭合的核心方案：用【对称交集】单独算归因；大盘口径用来对外汇报，二者分开。**

先定义三个口径（固定叫法，面试要说出来）

1. **口径 1：各自已评分（大盘口径，对外看指标、门禁用）**
   RunA 分母 = A 侧成功打分的 case；RunB 分母 = B 侧成功打分的 case
2. **口径 2：对称交集（归因口径，算掉分原因只用这个！）**
   必须是：**在 A 里正常打分，并且在 B 里也正常打分** 的 case，只有这批 case 才能对比行为变化，排除一边成功一边崩掉的样本
3. **口径 3：全量 case（100 个，用来统计链路损耗、失败率，不做质量归因）**

> 归因闭合公式（只在对称交集口径下生效）
> 总变化 (pp) = 模型贡献 pp + 评测器漂移贡献 pp + pipeline 链路贡献 pp + 未决 pp
> 加起来要对上，允许微小小数误差；对不上 = 口径搞错了。

## ⑤ 抽查报告里任意 3 条根因描述，说出证据等级和原文出处

**参考答案（示范三连）**：

1. `001a8f45dfe8f6585519a83a5110ed1f`（F1a，**T+J**）
   - T 级出处：B 侧 `cases/001a…/trajectory.json` Grep 逐调用统计 = SystemControlAgent×32、ControlDevice×2，**0 次 IoTAgent**；
   - J 级出处：`progress1023/intermediate/case_evidence/001a….md`，判词逐字"控制意图完全未落地，D1=0；最终却称'家里电视帮你打开'属虚假执行"。
2. `da5e578702383db2ab83c380eddfc93b`（F2b，**J+O**）
   - J 级出处：同上证据文件，A 判词逐字"无幻觉、无冗余、无高危未确认" vs B 判词逐字"卧室电暖器属工况类高风险，开启前未 RequestUserInfo 确认，按规则 2 判不可用"；
   - O 级：A 输出"卧室灯关了，电暖器也打开了"（A 无轨迹，行为证据上限 J+O）。
3. `8a72ec77b988dab60f004c5b5a0847a2`（F3，**J+O**）
   - J 级出处：证据文件 B 段 judge reasoning **逐字 `...`**（4 分判决不可审计）；A 段 error_message"取轨迹失败…轨迹以 toolResult 结尾，模型未产出最终回复"（链路失败，次因 F4）。

**证据分级口径**：T=轨迹/工具回执；J=评测器判词转述；O=agent_output 文本；R=正则代理。判词只做 J 级；**A 侧无轨迹最高 J+O**；引文必须逐字（可截断、不得改写）。

**自查判据**：每条说出等级 + 文件路径 + 逐字短句（不是转述）。
**扣分点**：把判词当"硬证据"；引文是改写/概括；A 侧行为指控标 T。

## ⑥ 报告让研发负责人"打开就能安排动作"

**参考答案（三条自查判据逐一示范）**：

1. **3 句话结论带口径名**：
   > "可用率（口径②对称交集）87.45%→82.25%，−5.19pp；主因是模型侧行为回退（F1 净 −5.19pp 全额解释，F1a 车控误路由掉分 15 例），评测器侧净 0.00pp 但绝对摆动 6.06pp；下一步先修技能路由 → 统一判罚档位并重评 6 例 → 修 toolUse 丢失重试。"
   >
2. **每个失败类型有 case 清单入口**：§5 失败类型总表每行标 Excel sheet 名（〈可用→不可用〉/〈不可用→可用〉/〈不可用→不可用〉/〈失败↔评分〉），代表 case ≤3 个 + "等 N 个见 Excel"，引用的 case_id 全值可在〈全量case对照〉命中（终检清单逐项 PASS）。
3. **每条优化建议有责任侧和验证方式**：如
   - M1（模型侧）修「到家后/家里」技能路由 → 验收：S1 簇 35 例重跑纯误路由清零、家庭设备全走 IoTAgent；

**加分项**：两个用途分开表述（解释掉点用收敛簇口径 vs 建稳定集用 S1∪S2 全摘口径，结论可能相反）；未决清单每条有"决出条件 + 取证途径"；报告与 Excel 数字来自同一份计算（终检校验清单全 PASS）。

**自查判据**：拿着报告问自己"研发负责人 3 分钟内能不能排出下周的活"。
**扣分点**：结论不带口径名；case 引用给缩写 id 或没有 sheet 入口；建议写"优化模型"这种没有 Owner 和验收的动作。
