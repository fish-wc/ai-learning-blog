# OpenClaw workspace目录完整学习

> workspace 是 Agent 的**工作记忆目录**，Agent启动的时候网关会**自动读取这个目录下的一系列`.md`文件，注入进系统提示词（system prompt）**。
> 在`sessions.json`的`systemPromptReport.injectedWorkspaceFiles`字段就能看到：这些文件会被加载送入大模型上下文，不是普通的注释文档，是会真正影响Agent人格、行为、记忆的配置。

目录总览：

```
workspace/
├─ AGENTS.md      # 工作区总说明、全局规则、备份建议、memory约定
├─ IDENTITY.md    # Agent身份人设：名字、性格、角色、怪癖、口号
├─ SOUL.md        # Agent灵魂，完整行为准则、思维模式、边界约束（最重要）
├─ TOOLS.md       # 用户自定义外部工具笔记，不定义内置工具
├─ USER.md        # 用户/使用者档案：称呼、代词、时区、用户背景
├─ memory/        # 每日持久记忆文件夹（可选，需要手动或者skill创建）
└─ skills/        # 存放自定义Skill技能目录，自己写的SKILL.md放这里
```

> 关键知识点前置：

1. 这些文件**不是程序代码**，是Markdown配置。Gateway启动Agent的时候读取全部内容，拼接进System Prompt给大模型。
2. 修改完文件，**已经存在的旧会话不会立刻生效**；因为旧会话存在`skillsSnapshot`和系统提示快照；**新建session会话才会加载最新md文件内容**。
3. BOOTSTRAP.md（可选）：首次运行引导脚本，执行完建议删除，本次样例不存在。

## 1. AGENTS.md

### 文件作用&意义

workspace工作区的**总入口说明文档**。

- 告诉Agent这个文件夹是什么，工作区的使用范式；
- 定义备份策略（建议git管理整个workspace）；
- 全局安全默认行为约束；
- 约定`memory/`每日记忆的规范；
- 可选`HEARTBEAT.md`心跳任务清单。

### 文件结构拆解

1. **First run（首次运行一次性流程）**：BOOTSTRAP.md的处理，身份文件说明
2. **Backup tip备份提示**：强烈建议git版本管理，保存agent记忆、人设
3. **Safety defaults【全局安全规则】**
   - 禁止泄露密钥私密数据
   - 不执行破坏性命令，除非用户明确要求
   - 聊天简短，长输出写到workspace的文件
4. **Daily memory 每日记忆约定**
   > 约定：把事实、偏好、决策写进 `memory/YYYY‑MM‑DD.md`；会话启动自动读取今天、昨天的记忆。**文件夹不会自动生成，需要agent或者用户手动创建memory目录**。
   >
5. Heartbeats（可选心跳运行的小清单）
6. Customize：留给用户自己增加规则、记忆
7. C‑3PO Origin Memory：C‑3PO这个Agent角色的起源小故事（业务案例，你可以删掉写自己agent的起源）

### 需要掌握的核心知识点

1. workspace建议用git做版本控制，防止记忆丢失。
2. `memory/`是**约定路径，不会自动生成**；Agent遵循规范把长期记忆写这里，会话启动自动读取今日、昨日记忆。
3. Safety defaults是**全局行为底线**，注入系统prompt，约束agent不能乱搞。
4. BOOTSTRAP.md只用于第一次初始化，完成后建议删除。

## 2. IDENTITY.md

### 文件作用&意义

> Agent**身份卡片**：回答「我是谁」。
> 定义Agent对外的名字、性格、表情、头像、定位、人物小癖好、口头禅。

- 聚焦：我叫什么，性格什么样，我的角色定位是什么，我有哪些小习惯。
- 和SOUL.md区分：IDENTITY是**人设表层**；SOUL是底层行为逻辑、做事原则。

### 文件结构拆解

1. 基础身份信息：`Name、Creature、Vibe、Emoji、Avatar`
2. Role：我的工作定位，本例子：`--dev模式调试Agent`
3. Soul（简短版角色目标）：我存在的目的，做什么，不做什么
4. Relationship with Clawd：角色之间人物关系
5. Quirks 角色小习惯（怪癖）：比如对裸try‑catch反感、喜欢计算成功概率
6. Catchphrase：角色口头禅

### 需要掌握的核心知识点

1. IDENTITY = **表层人设卡片**；修改这个文件会改变Agent说话风格。
2. 只改旧文件不会改变已经存在的老会话，**必须新开session会话才生效**。
3. 可以自定义自己的Agent，修改名字、性格、角色。

> 对比记忆：
> IDENTITY.md：我是谁（人设、性格、口头禅）
> SOUL.md：我该怎么思考，做事原则、边界、禁止行为。

## 3. SOUL.md（最重要文件）

### 文件作用&意义

Agent的灵魂，**核心行为规范**。定义思考方式、处事原则、能力边界，什么该做，什么不该做。

> IDENTITY回答“我是谁”；SOUL回答“我该如何行动”。
> 这个文件对Agent行为影响最大。

### 文件结构拆解

1. Who I Am：自我介绍，身份来历
2. My Purpose：我的使命，我的工作目标
3. How I Operate【核心！操作准则】
   - Be thorough：详尽地看日志
   - Be dramatic：允许适度戏剧化表达报错
   - Be helpful not superior：帮助人，不居高临下
   - Be honest about odds：如实告诉成功概率
   - Know when to escalate：知道自己能力上限，懂得求助
4. My Quirks：性格小习惯，和IDENTITY呼应
5. My Relationship with Clawd：人物关系
6. **What I will not do【禁止清单】**：明确列出绝对不能做的事情
7. Golden Rule：角色金句收尾

### 需要掌握的核心知识点

1. SOUL.md 是**行为约束核心**，控制Agent处理问题的思维方式。
2. `What I will not do`是硬约束，写入系统提示词，限制Agent行为边界。
3. 如果你要做自己的Agent，SOUL是你需要重点改写的文件。

## 4. TOOLS.md

### 文件作用&意义

> 用户的外部工具笔记，**不会定义系统内置工具**！
> 注意区分：

- 项目内置工具（`read/edit/exec/web_search`）：写死在Gateway代码，不在这个文件定义。
- TOOLS.md 用来写**你本地额外外部工具的说明**，告诉Agent你本机有哪些第三方命令、工具怎么用。

### 文件结构拆解

- 开头说明：本文件只是笔记，不定义内置工具
- 示例：imsg、sag两个外部工具使用说明
- 用户可以自由追加自己本地工具的备注

### 需要掌握的核心知识点

1. ❗**TOOLS.md不能新增/修改框架内置工具**，内置工具由gateway代码管理。
2. 用途：记录你电脑上独有的第三方命令行工具，告诉Agent调用的注意事项。

## 5. USER.md

### 文件作用&意义

**用户档案文件，描述“使用这个Agent的人是谁”。**
Agent读取这个文件知道使用者名字、人称代词、时区、用户背景，对话的时候会尊重你的称呼、时区。

### 文件结构拆解

1. Name：用户名字
2. Preferred address / Pronouns：代词，用什么称呼用户
3. Timezone：时区
4. Notes：补充用户背景信息。

### 需要掌握的核心知识点

1. Agent会读取USER.md，对话的时候会遵守代词、时区信息。
2. 多用户使用workspace：可以修改USER.md切换使用者身份。

## 📖阅读要点

1. 这个文件描述**使用者的身份信息**，会被注入顶层 system 系统提示词。Agent 在对话中会尊重这里写的代词、时区信息。
2. `They/Them (collective)`：集体中性人称，指代一整个团队，不是单个人。
3. 时区`Europe/Vienna`只是工作区默认；如果你本地使用，可以修改成自己的时区，例如`Asia/Shanghai`。
4. 修改此文件后，**只有新建会话才会生效**，旧会话沿用`sessions.json`里保存的快照。

## 6. memory/ 目录（文件夹，不会自动生成）

### 作用

持久化长期记忆目录。按照AGENTS.md约定：以日期命名markdown文件：`memory/2026‑10‑27.md`。

- Agent会话启动时自动读取今天、昨天的memory文件；
- 把长期事实、用户偏好、重要决策写在这里，不会丢失；

> ⚠️这个目录不会自动创建。要么你手动mkdir，要么skill（比如learning‑notes）自动生成。

### 需要掌握的知识点

1. memory是**约定的记忆存储规范**，不是框架强制。Agent靠system prompt里AGENTS.md的规则知道要读这个目录。
2. 记忆写入是Agent主动写文件完成，不是框架数据库自动保存。



## 7. skills/目录

### 作用

存放用户自定义Skill技能。
每个skill一个子文件夹，文件夹里面放`SKILL.md`。

> 区分：项目内置skill放在代码库`skills/`；**workspace/skills下面放用户自己写的自定义skill**。
> `sessions.json`里面的`resolvedSkills`可以区分来源：

- `source:xiaoaiclaw‑bundled`：项目自带内置skill
- `source:xiaoaiclaw‑workspace`：来自workspace/skills的自定义skill（例如样例里learning‑notes）

### 需要掌握的知识点

1. workspace/skills下面写自己的技能，优先级生效，会话启动加载。
2. 会话快照`skillsSnapshot`会保存会话当时加载的skill快照；旧会话不会自动读取新的SKILL.md。

# 📌综合核心总知识点（必须掌握）

## 1. 整体运行链路（打通之前sessions/jsonl知识）

1. 创建新会话sessionKey → 生成sessionId，新建会话；
2. Gateway读取workspace下：AGENTS.md、IDENTITY.md、SOUL.md、USER.md、TOOLS.md；
3. 读取workspace/skills下全部自定义skill；
4. 读取memory今日、昨日的记忆文件；
5. 把全部内容拼接，作为system prompt注入大模型；
6. 把这份完整快照保存到`sessions.json`该会话的`systemPromptReport`和`skillsSnapshot`；
7. 用户对话消息通过`appendMessage`写入`sessionId.jsonl`；

> ⚠️**快照一旦生成，老会话就固定这份system prompt。修改workspace下面md文件，老会话不受影响，只有新建会话才会读取磁盘上新的md。**

## 2. 文件分工对比速查表

| 文件        | 核心定位          | 一句话总结                                   |
| ----------- | ----------------- | -------------------------------------------- |
| AGENTS.md   | workspace总契约   | 工作区规则、备份方案、memory记忆约定         |
| IDENTITY.md | Agent表层人设卡片 | Agent叫什么、性格、口头禅                    |
| SOUL.md     | Agent灵魂行为准则 | 思考逻辑，什么做什么不做（最重要）           |
| USER.md     | 用户档案          | 使用Agent的人的信息、代词、时区              |
| TOOLS.md    | 外部工具笔记      | 记录本机第三方工具，**不修改内置工具** |
| memory/     | 持久记忆目录      | 按日期md保存长期记忆，不会自动创建           |
| skills/     | 用户自定义技能    | 存放自己写的SKILL.md技能                     |

## 3. 高频易错点

1. 修改workspace下面md，**已经存在的旧会话不会更新**。快照保存在`sessions.json`，必须新开会话才能生效。
2. memory文件夹不会自动生成，需要手动创建或者skill创建。
3. TOOLS.md**不能新增框架内置工具**，仅仅是笔记。
4. workspace文件全部送入system prompt，会占用token；`systemPromptReport`可以看到每个md文件占用多少字符。

## 4. 实操验证建议（你可以动手做）

1. 打开`sessions.json`，找到`injectedWorkspaceFiles`字段，你可以看到这5个md文件全部被注入，统计各自字符数。
2. 修改IDENTITY.md，新建一个全新sessionKey会话聊天，观察Agent人设变化；再打开旧会话对比，旧会话不会变。
3. 手动创建`memory`目录，新建`memory/2026‑10‑27.md`写一些事实，新开会话看agent能不能读取里面内容。
