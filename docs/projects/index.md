# 项目实践

项目是连接学习和求职的载体。这里记录从需求、架构、实现、评测到复盘的完整过程，优先选择能够体现问题分析和工程取舍的项目。

## 项目记录模板

每个项目至少回答以下问题：

- 要解决什么真实问题，用户和约束是什么？
- 基线方案是什么，为什么选择当前技术栈？
- 如何构造数据集和评测指标？
- 做过哪些对比实验，结果如何？
- 遇到过哪些失败，如何定位和修复？
- 如果流量、数据量或预算扩大十倍，系统哪里需要改？

## 作品集标准

一个可展示的项目应当有可运行的代码、清晰的 README、架构图或流程图、可复现的实验，以及对限制条件的诚实说明。不要只展示一个能调用模型的页面，要展示你对系统的理解。
