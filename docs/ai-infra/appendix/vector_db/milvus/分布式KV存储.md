# 分布式 KV 存储（分布式键值存储）

概述：多机器组成的键值数据库，**可靠存取少量元数据、配置信息**，etcd 就是最典型的一款。


详述：KV 即 Key-Value（键值对），`Key` 是唯一索引，`Value` 是对应数据，分布式代表数据分散存储在多台机器上，对外当作一个整体。通过Key查询Value，数据模型简单；高可用、一致性。典型代表：etcd。Milvus 使用 etcd 作为分布式KV存储，保存集群元数据、schema、节点状态，**不存储向量原始数据**。


## 特点
- 简单模型：只通过 Key 读写 Value，没有复杂 SQL；
- 高可用：节点挂了，数据不会丢；
- 强一致性可选（etcd 就是强一致分布式 KV）；
- 适合存元数据、配置、集群状态，**不适合存海量业务数据**。

## 典型代表
1. **etcd**：Milvus 用 etcd 存集群元信息（节点状态、collection schema、分片信息），强一致，少量数据。
2. Redis：也属于 KV，但一般不算典型分布式强一致 KV，多用于缓存。
3. Consul：同样可以做分布式KV+服务发现。

## 在 Milvus 里的场景
Milvus 的 RootCoord、所有节点都依赖 etcd：
- 保存集群所有元数据（有哪些集合、分片在哪、节点是否存活）
- 分布式锁、服务注册发现
> 注意：etcd **绝对不存向量本身**，向量数据存在对象存储。etcd 只存元信息。
