# 1. 磁盘架构是什么
**磁盘架构**，这里是消息队列/WAL组件的存储部署模型：传统消息队列（Pulsar、Kafka）的设计，**必须依赖本地磁盘（服务器本地硬盘）存放消息日志**。
- 数据先写入当前节点机器的本地磁盘；
- 为高可用，还会把日志复制到其他节点的本地磁盘做副本；
- 磁盘是核心持久化载体，不能去掉。
> 概述：组件自身需要占用服务器本地硬盘来存数据，就叫**依赖本地磁盘的架构**。

# 2. Woodpecker 的「零磁盘架构 Zero-Disk」
概述：**Woodpecker 本身不使用节点本地磁盘持久化日志数据，日志直接写入远端对象存储（MinIO/S3），本地磁盘只做临时buffer缓存，不需要用来永久保存日志。**

## 传统Pulsar/Kafka（非零磁盘）对比
1. 消息日志**永久保存在Broker节点本地磁盘**；
2. 高可用：多副本复制到多台机器的本地盘；
3. 如果节点本地磁盘损坏，消息有丢失风险；
4. 扩容麻烦：扩节点时要配套规划本地硬盘。

## Woodpecker零磁盘架构工作方式
1. 收到写入请求 → 数据先放在**内存缓冲区（MemoryBuffer）**；
2. 批量直接追加写入**远端对象存储**，日志主体永久保存在对象存储；
3. 本地磁盘**不承担日志持久化**的任务；本地就算宕机、销毁，日志还安全存在对象存储；
4. 日志流的元数据、消费checkpoint放在etcd。
> 本地磁盘仅仅是可选临时缓存，**不是持久化介质**，所以叫零磁盘架构。

### 补充：内存缓冲区 QuorumBuffer
独立模式下支持QuorumBuffer，在多节点内存之间做副本确认，**仍然不落地本地磁盘**，写完再持久化到对象存储，兼顾低延迟+持久可靠。

# 3. 零磁盘架构带来的优缺点

## 优点
1. **云原生弹性扩缩容**：新增/删除StreamingNode节点，不需要关心本地磁盘容量；节点可以随时销毁重建。
2. **运维简化**：不用管理多台机器本地磁盘、磁盘故障、磁盘容量告警，去掉磁盘运维负担。
3. **数据高可靠**：对象存储自带多副本，日志天然多副本持久化，不需要在机器本地之间做日志副本。
4. 资源解耦：计算节点（StreamingNode）和持久化存储（对象存储）分离。

## 缺点
1. 对象存储有网络IO开销，**单次写入延迟会比本地磁盘高**；所以Woodpecker默认会做批量攒包写入来降低开销。
2. 高度依赖对象存储服务稳定性，如果S3/MinIO不可用，WAL写入会失败。
