# 云原生（Cloud Native）
概述：**云原生是一套架构理念与技术栈，应用从设计之初就面向云环境（公有云/私有云/混合云）开发、部署、运维，充分利用云的弹性、分布式能力，而不是把传统单机应用简单搬到云上。** 四大核心技术，容器，容器编排，微服务，DevOps+持续交付（CI/CD）。

> 核心关键词：**为云而生，不是迁移上云**
> 传统上云：把物理机的程序打包丢到云服务器（“搬迁”），本质还是单体应用；
> 云原生：应用天生拆成微服务、跑在容器里，依靠云平台能力自动扩缩容、自愈。

## 四大核心技术（CNCF 定义）
1. **容器（Container）**
代表：Docker。把应用+依赖打包成独立容器镜像，环境一致，在哪都能跑，隔离轻量。

2. **容器编排（Orchestration）**
代表：Kubernetes(K8s)。管理大量容器：自动部署、故障自愈、弹性伸缩、负载均衡。容器挂了自动拉起新实例。

3. **微服务（Microservices）**
把大单体应用拆成多个独立小服务，各自独立开发、发布、扩缩容；服务之间通过API通信。

4. **DevOps + 持续交付（CI/CD）**
开发和运维协同，代码提交后自动构建、自动测试、自动部署。可以高频、安全地发布版本。

## 云原生能带来什么能力
- **弹性伸缩**：流量暴涨自动扩容实例；流量低谷自动缩容，节省资源。
- **故障自愈**：服务实例崩溃，平台自动重建，人工不用介入。
- **环境一致性**：开发、测试、生产环境镜像完全一致，避免“本地能跑，线上不行”。
- **可观测性**：日志、指标、链路追踪，方便排查分布式系统问题。

## 例子
传统单体：一个大程序部署在一台云服务器。服务器宕机 → 整个服务挂掉；流量变大只能手动加机器、手动部署。
云原生：拆成登录、商品、订单多个微服务，全部打包成容器交给K8s管理。订单服务压力大就自动多启动几个订单容器；某个容器崩了，K8s立刻新建容器顶上。

## 补充
云原生不绑定公有云，私有云也可以搭建云原生平台（K8s集群）。
现在向量数据库 Milvus、Qdrant 都是典型云原生应用，原生支持在K8s集群部署、分片扩缩容，刚好和前面FAISS（单机库）形成对比。
