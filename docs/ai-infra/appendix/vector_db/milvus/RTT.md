# RTT（Round-Trip Time）
> Round-Trip Time，往返时间。指数据包从发送端发出，抵达接收端，再携带**应答**返回发送端的总网络耗时，单位通常为ms。Woodpecker访问远端对象存储存在RTT开销，因此采用批量写入减少网络请求次数，降低整体写入延迟。

> 就是网络来回一趟耗时，不含业务计算时间，主要是网络传输延迟。
> 本地磁盘IO几乎没有跨机器RTT；对象存储是跨节点远程访问，RTT明显更大，这也是Woodpecker需要缓冲区做攒批的根本原因。
> 
## 在Woodpecker里为什么反复提RTT？
对象存储是远端服务，访问对象存储有一次完整RTT。
- 如果每一条向量写入，都直接调用一次对象存储：每一条都要等待一次RTT，延迟很高。
- Woodpecker用**攒批写入**，把多条日志打包成一次请求，**一次RTT传输一大批数据**，摊薄网络开销，降低整体延迟。

### 结合前面QuorumBuffer的例子
> 一次RTT完成副本复制：
数据在Woodpecker集群内部节点之间同步，一次网络往返就能完成多数派副本确认，不需要多次网络来回，降低写入延迟。

## 区分两个容易混淆的概念
1. **RTT**：网络来回耗时（单纯网络）
2. **Latency（延迟）**：完整请求耗时，= RTT + 服务端处理耗时
